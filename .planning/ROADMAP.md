### Phase Details

#### Phase 152: Asset Completeness in bs-build-chunk
**Goal**: A game generated by `bs-build-chunk` never renders a broken `<img>` for card/piece art — either the skill emits the assets it references, or the generated UI degrades cleanly to its drawn fallback, and the skill's own test step fails an asset-referencing-but-asset-less game instead of passing it green.
**Depends on**: Nothing (first v4.7 phase; independent of Phase 153)
**Requirements**: ASSET-01, ASSET-02
**Success Criteria** (what must be TRUE):
1. Regenerating a game via the `bs-build-chunk` pipeline (e.g. re-running chunk-1 against Go Fish) produces zero broken `<img>` elements when browser-verified, without hand-adding an asset set afterward.
2. If a hypothetical chunk references `$images` paths with no corresponding asset files and no fallback guard, the skill's automated build/test step fails (not passes green) — proven by a deliberate before/after test case.
3. The fix lives in the skill/scaffold layer (`src/cli/slash-command/bs/build/*.md` and/or the scaffold UI template), not as a one-off hand-patch to a single generated game.
**Plans**: TBD

#### Phase 153: Dev-Host Multi-Client Turn-Desync Fix
**Goal**: The dev-host multiplayer path keeps every connected client's turn view (`isMyTurn`/`currentPlayer`) consistent with the server across reload, reconnect, and AI-seat takeover — a client is never told it's its turn when it isn't.
**Depends on**: Nothing (independent of Phase 152; can run in parallel, but numbered after it per milestone's suggested order)
**Requirements**: DEVHOST-01, DEVHOST-02
**Success Criteria** (what must be TRUE):
1. A repeatable multi-client scenario (reload/reconnect storm and/or AI-seat takeover against `MultiplayerHost`/`SnapshotSessionHost`) reliably reproduces the stale-turn-view symptom before any fix lands, with root cause identified — not just "didn't reproduce."
2. After the fix, the same scenario passes in a multi-client regression test (fails on pre-fix code, passes on post-fix code).
3. A human or scripted 2-client dev-host session (reload mid-game, reconnect, then hand a seat to AI and back) never shows "your turn" on a client whose turn it is not.
**Plans**: TBD

#### Phase 154: MERC Re-Vendor
**Goal**: MERC's vendored BoardSmith copy carries the DEF-B dev-host lost-update fix (`281e8155`) plus the v4.7 asset and dev-host fixes, proven by MERC's own test suite staying green.
**Depends on**: Phase 152, Phase 153 (the re-vendor must carry all v4.7 fixes, not just DEF-B)
**Requirements**: VENDOR-01
**Success Criteria** (what must be TRUE):
1. `~/Dropbox/MERC/BoardSmith/MERC`'s vendored copy is refreshed to current BoardSmith `src/` (post Phase 152/153), following MERC's own re-vendor pattern from its commit history.
2. MERC's full test suite passes against the re-vendored copy at the same or better pass rate as its last known-green baseline (738/7 per prior milestones).
3. No MERC-side source changes were needed to absorb the re-vendor (or if any were needed, they're documented as a real MERC-side compatibility gap, not silently patched over).
