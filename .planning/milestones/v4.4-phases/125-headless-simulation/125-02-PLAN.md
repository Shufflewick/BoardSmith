<objective>
Add the `boardsmith simulate` CLI command: seeded, headless batch play of a project's game with pass/stuck/error reporting, a human-readable table by default and `--json` for agents, and a non-zero exit code when any game fails. Implements SIM-02.

Purpose: Developers and CI need to headlessly audit a game ("do 10 seeded games all complete without getting stuck?") and reproduce failures exactly. The simulation loop (`simulateRandomGames`) and the rules-loading mechanism (`dev.ts`'s esbuild live-bundle) already exist — this phase wires them into a CLI command, mapping the existing result shape to the CONTEXT-specified output and exit semantics. No new simulation loop, no new dependencies.

Output: `src/cli/commands/game-runtime.ts` (shared loader extracted from `dev.ts`), a refactored `dev.ts` consuming it, `src/cli/commands/simulate.ts`, registration in `cli.ts`, and `src/cli/commands/simulate.test.ts` + a real-game smoke run against `~/BoardSmithGames/go-fish`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| project rules source → CLI process | `boardsmith simulate` esbuild-bundles and dynamic-imports the project's rules module — arbitrary code from the project being simulated executes in the CLI's Node process |
| --seed input → simulation outcome | Seed fully determines results; the same-seed-twice contract is what makes CI/audit trustworthy |
| simulation outcome → exit code | CI relies on non-zero exit to detect failures; a wrong mapping = silent CI pass |
