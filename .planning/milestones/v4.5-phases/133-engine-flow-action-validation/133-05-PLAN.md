<objective>
Implement ENG-07 (F27): `switchOn` with no matching case and no default THROWS an actionable error naming the stringified value and the available case keys, instead of silently marking the frame completed and continuing.

Purpose: A silent no-op on an unmatched `switchOn` hides a real game-logic bug (a mistyped phase key like `'combatt'` just does nothing). Per the locked decision this must fail loudly, matching the loop `maxIterations` throw precedent from v4.3 Phase 120. `SwitchConfig` inherits an optional `name` from `BaseFlowConfig`, so the message may include the node name (like the loop precedent) but the required baseline is the generalized form. A plain thrown `Error` propagates through `runner.ts`'s existing catch into `{success:false, errorCode: ENGINE_ERROR}`, exactly like `resumeSimultaneousAction`'s existing throws.
Output: The unmatched-case throw in `executeSwitch` plus a red-first regression test.
</objective>
