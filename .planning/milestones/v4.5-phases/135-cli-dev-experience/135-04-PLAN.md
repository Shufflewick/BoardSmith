<objective>
Make the publish manifest DERIVE player count from the compiled `gameDefinition` instead of forwarding whatever `playerCount` happens to be in `boardsmith.json`. `build.ts` currently emits `{ ...config, buildTime, version, engineProtocol }` — a raw spread that silently carries any stale key. This plan adds a positive `loadGameDefinition` read and writes an explicit derived `playerCount: { min, max }`.

Purpose: this is the load-bearing half of CLIX-01 (Pitfall 1). Deleting the scaffold key (Plan 03) is not enough — the manifest must actively compute the value so it can never come from raw config even if validation is bypassed or a stale key lingers. `build.ts` today never loads the rules in Node, so this adds the `getProjectContext` + `.boardsmith` tempDir + `loadGameDefinition` setup already used by `simulate.ts`.
Output: manifest with a derived playerCount + a new build.test.ts (build.ts has zero coverage today).
</objective>
