unrelated game-repo test failures logged as accepted follow-up debt rather than swept under the rug.
Status is `tech_debt`, not `passed`, because that game-side debt and two carried-forward Phase 159/160
warnings are real, worth a human decision on scheduling, and should not be silently closed out with the
milestone.

## 2. PLATLOG-01 / Phase 165 — Deferral Legitimacy (independently verified)

REQUIREMENTS.md marks PLATLOG-01 `[~] DEFERRED TO PLATFORM TEAM`, and ROADMAP.md Phase 165 has no
plan/executed-phase directory under `.planning/phases/` (correctly — there was nothing in this repo to
fix). This audit independently re-ran the underlying claim rather than trusting the note:

```
grep -rn "DRAWDROP" /Users/jtsmith/BoardSmith/src        → 0 hits
grep -rln "DRAWDROP" ~/BoardSmithGames/{lanternfall,seven,one-two-punch,doom-machine}/src → 0 hits
grep -rln "DRAWDROP" ~/BoardSmithGames2/seven/src         → 0 hits
```

Cross-checked against the lab's own finding doc
(`~/BoardSmithLab/findings/boardsmith-platform-drawdrop-debug-logging.md`), which documents the same
zero-hit greps against the library and Doom Machine repos and identifies the `[DRAWDROP-SRV]` /
`[CONVEX M(pieces:*)]` markers as originating from the **deployed** platform's Convex backend — a layer
this repo cannot reach or fix. 169's crosswalk (`169-CROSSWALK.md` §"No-op / withdrawn / out-of-scope
items") independently re-confirms the same zero-hit grep against all five game repos as part of the
final sweep.

**Verdict: legitimate out-of-scope deferral, not a silently-dropped gap.** D32 is the one defect in
D1–D32 with an ABSENT verdict in the library-fix-present checklist, and that ABSENT is correct and
expected (there is nothing to gate in this repo) — not a missed fix.

  panel and MCTS. Core C.2 delivered; this is a documented edge case.
- **v4.8-MCTS-UNDO** (surfaced by 159-03): MCTS incremental `undoCommands` doesn't revert plain-property/

None of the above were silently dropped — every item has a name, a root-cause note, and a recorded
recommendation for a future pass. They are the reason this audit's status is `tech_debt` rather than

schedule the game-repo hidden-zone follow-up and the two MCTS/undo edge cases, rather than have them
