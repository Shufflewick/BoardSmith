<objective>
Close the panel half of AI-01 and deliver feature C.2. `buildPickMetadata` currently emits
`base.multiSelect` ONLY when `typeof multiSelect !== 'function'` (`action-metadata.ts:148-158` choice,
`:202-212` elements). For a function-valued multiSelect the panel therefore sees `sel.multiSelect ===
undefined`, the `ActionPanel.vue:901` checkbox branch is skipped, and the pick falls back to
single-select → "requires ≥2, got 1" (Doom BS-5).

Purpose: route both metadata sites through the SAME `resolveMultiSelect` helper Plan 01 created, so the
panel and MCTS can never disagree on whether a selection is multi-select. When the function resolves to
a concrete `{min,max}`, emit it as `base.multiSelect` and the existing widget + controller
(`ActionPanel.vue:901`, `useActionController.ts:1785`) engage with NO further change.

Output: rewired `buildPickMetadata` (choice + elements) and net-new metadata regression proving the
function form now emits resolved `{min,max}` and the panel completes natively (C.2).
</objective>

<decisions>
## Locked decisions implemented here (CONTEXT §multiSelect Resolution)

- **D-01 (single source of truth):** BOTH metadata sites call the SAME `resolveMultiSelect` Plan 01
  created. Do NOT inline a second copy of the function-eval logic here — the whole point is that MCTS
  and the panel resolve identically. (Depends on Plan 01; that is why this is wave 2.)
- **Concrete → emit:** a function that resolves to a concrete `{min,max}` emits `base.multiSelect` so
  the widget engages — no single-select fallback for a selection that resolves to a real multiSelect.
- **undefined → omit:** a function returning `undefined` emits NO multiSelect metadata (legitimately
  single-select). This preserves current correct behavior for genuinely-not-multi selections.
- **No panel change** (RESEARCH): the widget + controller already consume `{min,max}`. This plan is
  metadata plumbing only — no UI-SPEC, no `ActionPanel.vue` / `useActionController.ts` edit.
- **Throw semantics:** if `buildPickMetadata` runs in a state where the function throws, the throw
  propagates (fail loud, same contract as Plan 01) — metadata construction does not swallow it.
</decisions>
