<objective>
Close SIM-04 (D27): during a simultaneous step the shell shows a contradictory seat status ("Your move"
+ "waiting") and leaks a commit — a seat that already committed can re-submit. The status is derived
from turn-based (single `currentPlayer`) assumptions that are wrong when `awaitingPlayers` is non-empty.

Purpose: to a Seven player this presents as the action panel saying "act" while the status says "wait".
`availableActions` (`GameShell.vue:426`) already checks `!myPlayerState.completed`, but the waiting-list
strings and the execute guard do NOT — that inconsistency is the defect, and the ungated execute path is
a real double-commit integrity leak.

This plan is UI-only and file-disjoint from the engine/session plans (01, 02). It has no code dependency
on them: it reads `flowState.awaitingPlayers[].completed`, which is present on the live `getState()`
regardless of Plan 01's checkpoint-copy fix.

Output: a self-filtered awaiting list, a simultaneous-appropriate status (not currentPlayer-derived), an
execute guard on the viewer's own `completed` flag, and a RED→GREEN component test with adversarial
verification of the commit-leak closure.
</objective>
