<objective>
Close the server-side half of DEVHOST-01 (D13): let a declared `gameOption`/`preset` be SELECTED
(not frozen to defaults) both from the CLI (`--game-option k=v` repeatable, `--preset name`) and over
the wire (so Plan 03's browser selector has a host to talk to), with the selected values flowing into
the `start` op.

Purpose: today the start options are frozen to `.default`:
`baseGameOptions = Object.fromEntries(devConfig.gameOptions.map(o => [o.id, o.default]))`
(`dev.ts:696`) → spread into the `start` op at `multiplayer-host.ts:527`. The option DEFAULTS already
reach the start op, but there is (1) NO way to pick a non-default value, (2) `gameDefinition.presets`
is NEVER read (0 grep hits; `DevHostConfig` has no `presets` field), and (3) the boardsmith.json vs
gameDefinition option merge REPLACES rather than merging (`dev.ts:557` `...(gameOptions && {gameOptions})`).

Output: `--game-option`/`--preset` flags (cli.ts + dev.ts) resolving selected values into
`baseGameOptions`; `gameDefinition.gameOptions` merged with boardsmith.json (game definition
authoritative) and `gameDefinition.presets` surfaced in `DevHostConfig`; and a host-side selection
message that applies chosen option/preset values to the (re)start op. Regression coverage proves a
selected value — not `.default` — reaches the start op.
</objective>

<decisions>
## Locked decisions implemented here (CONTEXT.md D13)

- **Both entry points.** CLI flags (`--game-option k=v` repeatable, `--preset name`) for scripted/agent
  starts AND a host-side selection message for the browser selector (Plan 03 builds the UI on top).
- **Read the game definition.** Merge `gameDefinition.gameOptions` with `boardsmith.json`
  (game definition AUTHORITATIVE on key conflict), and READ `gameDefinition.presets` into
  `DevHostConfig.presets`. Do NOT keep the replace-not-merge behavior at `dev.ts:557`.
- **Selection is pre-start.** Selected values flow into the `start` op's gameOptions, replacing the
  frozen `.default`-only `baseGameOptions`. A preset APPLIES its bundle of option values (and player
  count if the preset declares one) — selecting a preset is a shortcut for setting the underlying
  options. Changing after start restarts.
- **Validate the selection (T-161-02/03).** A `--game-option`/wire key not in the declared
  `gameOptions`, or a select value not among the option's declared choices, is REJECTED with an
  actionable error — the host must not inject arbitrary keys into the start op.
- **Claude's Discretion (CONTEXT):** exact `--game-option name=value` parsing (first-`=` split;
  repeatable), and the exact name/shape of the host selection message.
- Error messages stay actionable and leak no paths/line numbers/stack traces.
</decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI flag → dev host | `--game-option k=v` / `--preset name` are developer-supplied strings parsed into the start op's gameOptions |
| connected client → host `configure` message | Any client on the dev-host WS can request an option/preset selection that alters the shared start op |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-161-02 | Tampering | host `configure` handler — a client injects an undeclared gameOption key (or out-of-choices value) into the start op | mitigate | Validate every selected key against the merged declared `gameOptions` (and select choices) before applying; reject with an actionable error; adversarial undeclared-key test (Task 1) |
| T-161-03 | Tampering | `parseGameOptionFlags` — a malformed `--game-option` (missing `=`) is silently dropped | mitigate | Fail-loud `DevFlagError` on a missing `=` (Task 1), matching the `parsePositiveInt`/`parseAiSeats` idiom |
| T-161-05 | Elevation of Privilege | a `configure`+restart resets the shared game for every seat | accept | The dev host is a LOCAL, single-table trusted tool; every connected client is a co-located playtester with equal authority over the one shared game (same disposition as the Phase 157 restart path). No new remote surface. |
| T-161-SC | Tampering | npm/pip/cargo installs | N/A | No package installs in this phase (RESEARCH.md: no new libraries) |
</threat_model>
