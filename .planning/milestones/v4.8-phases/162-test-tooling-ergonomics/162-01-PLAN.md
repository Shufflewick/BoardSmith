<objective>
Close TOOL-01 (D17) and TOOL-02 (D18): stop `scanAssetReachability` from false-FAILing on `<img`
inside code comments, and put it on the published `boardsmith/testing` export surface so games can
call the build gate without hand-rolling a second scanner.

Purpose: the asset-reachability gate (`asset-scan.ts`) tests each source line against
`BARE_IMG_TAG` with NO comment stripping (`:73-83`), so a commented-out `<img` (`// <img`,
`/* <img */`, `<!-- <img -->`) produces a build-blocking FAIL even though nothing renders it — this
is what broke Lanternfall's build. Separately, the function is exported from its own module but no
published barrel re-exports it (`package.json` exports has no `./cli`), so OTP could not import it.

Output: comment-span stripping (all three styles, block state tracked across lines) in front of the
regex test; an additive re-export from `src/testing/index.ts`; and net-new RED-first regression
coverage for both defects.
</objective>

<decisions>
## Locked decisions implemented here

- **D17:** Strip JS line (`//`), JS block (`/* */`), and Vue HTML (`<!-- -->`) comment spans BEFORE
  the `BARE_IMG_TAG` test, **tracking block-comment / HTML-comment open state across line
  boundaries** (a `/* ... */` or `<!-- ... -->` can span many lines). Only live markup reaches the
  regex. Line numbers reported in `AssetViolation` MUST stay correct — strip comment *content* to
  spaces (or otherwise preserve line indices), do NOT drop lines. Do NOT strip `<img` inside a
  genuinely-live string literal that is not a comment (per RESEARCH Pitfall — the fix is
  comment-scoped only).
- **D18:** Re-export `scanAssetReachability` (and its `AssetViolation` type) from
  `src/testing/index.ts` — additive. It is a build/test gate helper and `boardsmith/testing` is the
  right, already-published home (no new `./cli` barrel). The additive export MUST NOT break the
  existing internal relative-path importers (`asset-scan.test.ts`, the `bs-build-chunk` skill).
- Claude's discretion: a small line-oriented state machine vs a tokenizer for comment stripping —
  either is fine provided all three styles + cross-line block state are handled and live string
  literals are untouched.
</decisions>
