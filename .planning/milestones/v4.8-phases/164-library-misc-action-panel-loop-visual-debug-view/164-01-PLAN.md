<objective>
LIBX-02 (D29): Let `loop()` express a genuinely unbounded game via an explicit `unbounded: true` valve that makes `maxIterations` optional, while keeping the bounded per-loop cap-hit as a loud safety assertion and retaining the whole-flow runaway tripwire.

Purpose: Today `loop()` throws at construction if `maxIterations` is undefined, so an unbounded game (Lanternfall) cannot be expressed without a lie (an arbitrary huge cap that would then throw mid-game as a "safety assertion, NOT a terminator"). The `unbounded: true` opt-in is greppable, self-documenting, and fail-loud if misused.
Output: `LoopConfig.unbounded`, updated `loop()` construction guard + message, `executeLoop` Infinity fallback, PROC-01 tests, doc updates.
</objective>
