<objective>
Fix the SKILLDEF-01 session-lock defect: the `bs-build-chunk` close ceremony never releases its
lock, fabricates lock timestamps, and can overwrite CHUNK.md — causing a same-day resume to
false-alarm as a live concurrent session (the run-004 filing). Fix it at the root: give the lock a
clock-read timestamp and a session/chunk identity, add a terminal lock-RELEASE step to `close`,
make close's writes append-only with the release as the terminal atomic write, and teach Step 0 to
recognize a released/no-lock state so a clean close leaves nothing to false-alarm on.

Purpose: A cleanly-closed chunk must leave `Session Lock: none`, so the next same-day session sees
no live lock and resumes without warning. The timestamp must never be invented.
Output: Edited skill/spec/template source (git-tracked repo copies) + failing-first drift tests.
</objective>
