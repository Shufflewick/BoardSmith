Complete FLOW-01/03 devtools parity (v4.3 hard rule: introspection parity in the browser). GameShell is a client over HTTP/WS — it holds no engine Game — so the flow-debug and pending-action data must travel through the existing session broadcast to the client, then into the `__BOARDSMITH_DEVTOOLS` bridge. Purpose: An agent/developer can read the current flow position and the acting seat's pending action from the dev host bridge, matching engine values, without a Node terminal.
Output: Serializable flow-debug + own-seat pending-action in the broadcast, forwarded to the devtools bridge and exposed as two new window getters; browser-verified.
</objective>
