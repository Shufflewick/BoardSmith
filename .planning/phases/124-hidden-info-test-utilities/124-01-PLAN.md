<objective>
Deliver VIS-01: per-seat element-visibility assertions that never drift from the wire serializer —
including games that define a custom `static playerView` hook.

The locked CONTEXT.md decision is "visibility computed from the SAME serialization path the wire
uses." The wire path is `Game.toJSONForPlayer(seat)`, which runs the per-element `isVisibleTo`
filter AND THEN a `GameClass.playerView(state, seat, game)` post-transform (game.ts:2813-2816).
Deriving visibility purely from `element.isVisibleTo(seat)` bypasses that post-transform and would
drift for any game defining `static playerView`. Therefore VIS-01 derives visibility from the ACTUAL
final serialized output of `game.toJSONForPlayer(seat)` — an element is *visible* iff its node is
present in that final tree and NOT flagged `__hidden`. `element.isVisibleTo(seat)` is used only as a
fast path when `GameClass.playerView` is undefined (where it provably matches the final tree, since
no post-transform runs).

Purpose: Developers assert hidden info stays hidden without hand-parsing ElementJSON, with zero
drift from the exact bytes each seat receives.
Output: `src/testing/visibility.ts` (new), TestGame methods, `assertHidden`/`assertVisible`
in `assertions.ts`, barrel exports, and colocated tests.
</objective>
