<objective>
Close ERR-04: a connected dev-host client can pull captured server-side errors/warnings over a `debug:logs` WS op instead of watching the Node terminal.

Purpose: Today dev-host server-side errors (session errors, persistence failures from ERR-03, structured warnings) are only visible in the terminal. Per RESEARCH Pitfall 3, `debug:logs` CANNOT route through the pure/stateless `executeOp` (documented "no memory between calls") — it must be a host-lifecycle op like `demoStart`/`demoStop`, backed by a ring buffer that lives in the dev-host process. Per Pitfall 5 / security, the session layer must NEVER import the dev-host log-capture module: the `onPersistenceError` hook is injected, and the dev host supplies a callback that calls into its own capture module.

Output: A new `log-capture.ts` ring buffer, the `debug:logs` op wired through the bridge and handled as a host-lifecycle op, the dev host feeding persistence/console errors into the buffer, and a DebugPanel Logs tab.
</objective>
