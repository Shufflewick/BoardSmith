# Phase 134 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase type note:** this is a guardrails/fix phase, not a new-screen phase. The only genuinely visual deliverable is UIX-01 (a centrally-surfaced action-failure toast, reusing the existing v4.0 Slate `--bsg-*` token system and the existing `useToast()`/`Toast.vue` mechanism). SESS-01, UIX-02, UIX-04, UIX-05 are composable API contracts (return values, devWarns, prop gating, hook accumulation) with no new visual surface. UIX-03 is a dev-mode `console.error` + docs section, not a rendered UI element. No new dependencies, no new design language, no new components.

## Copywriting Contract

All copy below follows CLAUDE.md's error-message rule: actionable, no internal details leaked (no stack traces, line numbers, internal file paths, or raw error object dumps).

| Element | Copy |
|---------|------|
| UIX-01 — action-failure toast (server/engine rejected action) | Surface the engine's `error` string verbatim if present (engine errors are already written to be actionable per Phases 132/133's devWarn conventions — e.g. "putInto() target is a descendant of..."); if no `error` string is present, fall back to: `"{actionName} failed — try again or check the current selection."` Never render `undefined`, `[object Object]`, or a raw exception's `.stack`. |
| UIX-01 — `start()` called for unavailable action (devWarn, not user-facing) | `` `start('{actionName}') was ignored: '{actionName}' is not in the current player's available actions. Check availableActions before calling start(), or wait for the action to become available.` `` |
| UIX-02 — `fill()` given a scalar for a multiSelect pick | `` `fill('{selectionName}', ...) rejected: '{selectionName}' is a multiSelect selection (min {min}, max {max}) and requires an array. Use toggleMultiSelect()/confirmMultiSelect(), or pass an array directly to fill().` `` (mirrors the existing `toggleMultiSelect` reverse-guard wording at `useActionController.ts:1729-1733` — same voice, opposite direction) |
| UIX-03 — responsive board collapsed to 0×0 (dev-mode `console.error`, not a toast — this never reaches players) | `` `Custom board failed to render: the #game-board slot measured 0×0 after game state arrived. This usually means a percentage-width or container-type board is collapsing inside GameShell's zoom container ('.game-shell__zoom-container { width: max-content }'). Give your board's root element a definite width (not 100%) or see the "Board Sizing" section of docs/custom-ui-guide.md.` `` |
| UIX-04 — `dragProps()` returns inert props when `when` is false (no copy — behavioral only: `draggable: false`, no handlers attached; no toast, no console output — this is expected, silent, correct behavior per the documented option) | N/A |
| UIX-05 — `setBeforeAutoExecute()` hook accumulation (no user-facing copy; JSDoc only) | JSDoc updated: replace any "REPLACES the previous hook" language with "registers an additional hook; hooks run in registration order; call the returned function to unregister this hook." |
| SESS-01 — `session.runner` facade: attempting to call `.performAction` on the read-only facade | TypeScript compile-time error is the primary guard (the facade's type has no `performAction` member) — no runtime copy needed for the typed path. If an untyped/JS caller reaches for it at runtime, throw: `` `session.runner is a read-only facade (state/view/history only). Call session.performAction(...) instead — it handles persistence, broadcast, and checkpoints that calling the engine runner directly would silently skip.` `` |
| Destructive confirmation | None in this phase's scope — no new destructive UI action is introduced. `fill()`/`start()`/`dragProps()`/`setBeforeAutoExecute()`/`session.runner` are developer-facing API contracts, not player-facing destructive flows. |

**Toast timing/dismissal (UIX-01):** reuse `useToast().error()`'s existing default duration (4000ms per `useToast.ts`) and existing manual-dismiss affordance in `Toast.vue` — do not introduce a new duration or dismissal pattern for this phase's failure toast. If a game legitimately needs a longer-lived error (e.g. a persistent "thinking" toast pattern already exists at `GameShell.vue:876` for AI hints), that is out of scope here; the UIX-01 failure toast is a standard transient `toast.error()` call.

## Interaction & Accessibility Contract (UIX-01 specifics)

- **Placement:** GameShell centrally watches `actionController.lastError` (plus failed `execute()`/`fill()` results) via a `watch()` in `GameShell.vue` (same file that already owns `toast`, `politeMessage`/`assertiveMessage`, and the AI-hint/undo toast calls at lines 656–938). Do not add a second toast-owning component — one chokepoint, matching the existing pattern.
- **Parity (CLAUDE.md hard rule):** the failure toast must fire identically whether the failing action was initiated from the shipped ActionPanel or a custom UI driven through `useBoardInteraction` — both paths already flow through the same `useActionController` instance, so watching `lastError` at the GameShell level satisfies parity by construction. Do not add a parallel error-surfacing path inside ActionPanel.
- **aria-live behavior:** `GameShell.vue` already exposes `role="status" aria-live="polite"` (`politeMessage`, line 1849) and `role="alert" aria-live="assertive"` (`assertiveMessage`, line 1850) live regions established for WCAG 2.2 AA in v4.0. Route the UIX-01 failure text into the existing `assertiveMessage` live region (action failures are assertive-priority, matching how `toast.error()` calls elsewhere in this file are already treated) — do not create a third live region.
- **Non-color cue:** per v4.0 WCAG 2.2 AA precedent, the error toast must not rely on `--bsg-danger` color alone — confirm `Toast.vue`'s error variant already carries an icon/shape or text label distinguishing it from success/info (it should, per existing v4.0 work); if not, that is a pre-existing gap outside this phase's scope — flag, do not silently expand scope to fix it here.
- **Return-value contract:** `start()` changes from `Promise<void>` to `Promise<ActionResult | ValidationResult>`-shaped result (reuse the existing `ActionResult`/`ValidationResult` interfaces already defined in `src/ui/composables/useActionControllerTypes.ts:122-134` — do not invent a new result type). Callers that ignore the return value still get the toast (loud-by-default per Pit of Success); callers that await it get a programmatically-checkable result. Exact unification of `start()`'s result shape with `execute()`'s existing shape is Claude's discretion per 134-CONTEXT.md — prefer reusing `ActionResult` over introducing a third shape.

## FLAGS (genuinely open — not resolved by CONTEXT.md or existing code)

Executor must verify `Toast.vue`'s markup during implementation; if a WCAG 2.2 AA non-color cue is missing, flag it back to the phase owner rather than silently adding new icon assets (no new dependencies).
2. **UIX-03 structural CSS fix vs. dev-error-only** — 134-CONTEXT.md defers to research: "adopt [a structural CSS fix] ONLY if proven not to break the v4.0 zoom-to-fit architecture; otherwise the dev-error + docs is the complete fix." This UI-SPEC treats the dev-error + docs path as the default/safe contract; a structural fix, if pursued, must not alter any token, spacing, or color value declared above — it is a layout-mechanics change, not a design-contract change, and does not require re-verification against this spec if it stays purely structural (width/container-type CSS).
3. **Exact console.error call site (GameShell vs. useAutoZoom)** — left to implementation per CONTEXT.md's "Claude's Discretion"; does not affect this design contract since console output has no visual/token surface.
