<objective>
Add a `useAnnouncer()` composable to `boardsmith/ui` that lets any game component (custom UI or AutoUI) announce state changes to screen readers by writing through GameShell's existing live-region refs — no new DOM nodes, no new architecture. This is the LIB-01 library prerequisite that gates the v4.6 per-chunk a11y floor.

Purpose: Games can announce their own state changes (e.g. "3 cards remain") without modifying GameShell, using the same live regions and postMessage relay GameShell's built-in announcements already use.

Output: `src/ui/composables/useAnnouncer.ts` (+ unit test), GameShell wiring, public export, and a component parity/relay test.
</objective>

<locked_decisions>
From 140-CONTEXT.md (NON-NEGOTIABLE):
- API: `const { announce } = useAnnouncer()`; `announce(message, { assertive?: boolean })`. Polite by default; assertive opt-in.
- Minimal API scope: only `announce()` — no `clear()`, no raw ref exposure.
- Used outside GameShell (no provider): no-op + one-time dev-mode `console.warn` (via `devWarn`), following the `useAnimationEvents` inject-with-undefined pattern.
- Writes to GameShell's existing `politeMessage`/`assertiveMessage` refs via provide/inject — NO new DOM nodes.
- Repeated identical messages use clear-then-set (reset to '', `nextTick`, write) so screen readers re-announce duplicates.
- Collisions with GameShell's own announcements: last-write-wins, no queue.
- Export from `src/ui/index.ts` alongside `useBoardSize`.
- Each announce also fires the existing `boardsmith-a11y` postMessage relay (`emitAnnounce`).
- AutoUI parity via the same inject path; a test must prove it.

Planner-resolved (research Assumptions A1/A2, flagged for planner decision):
- **A1 — `announce()` return type is `void`** (matches the locked "just call it" ergonomic `announce(...)`, no `await` required by callers). Internally clear-then-set is done synchronously-clear + `nextTick` write. Tests observe by awaiting `nextTick()`. Do NOT return `Promise<void>`.
- **A2 — clear-then-set applies uniformly to EVERY `announce()` call** (not conditionally on detected duplicates). Matches CONTEXT's "simple, no queue" philosophy.
- devWarn key is the single static string `'useAnnouncer-no-provider'`.
- Mirror the two-function shape: `createAnnouncer(options)` factory + `provideAnnouncer(instance)`, matching `createAnimationEvents`/`provideAnimationEvents`.
</locked_decisions>

<interfaces>
Target public contract for src/ui/composables/useAnnouncer.ts:

```typescript
export interface UseAnnouncerReturn {
  announce: (message: string, options?: { assertive?: boolean }) => void;
}
export interface CreateAnnouncerOptions {
  politeMessage: Ref<string>;
  assertiveMessage: Ref<string>;
  emitAnnounce: (level: 'polite' | 'assertive', text: string) => void;
}
export const ANNOUNCER_KEY: InjectionKey<UseAnnouncerReturn>;
export function createAnnouncer(options: CreateAnnouncerOptions): UseAnnouncerReturn;
export function provideAnnouncer(instance: UseAnnouncerReturn): void;
export function useAnnouncer(): UseAnnouncerReturn; // never undefined — no-op fallback + devWarn
```
