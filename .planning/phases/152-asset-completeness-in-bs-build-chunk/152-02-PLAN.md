<objective>
Fix the identical unguarded-`<img>` bug that lives in BoardSmith's own AutoUI renderers
(`CardRenderer.vue`, `PieceRenderer.vue`). Today they branch only on "does `$images` exist," never
on "did the URL resolve" — so a `ui: auto` game (the scaffold default) is exposed to DEF-A's exact
failure mode even though `AssetImage.vue` (plan 01) only covers the custom-UI path. This is a normal
Pit-of-Success library fix (2 existing files, already in this repo's test suite) that fixes every
AutoUI game at once.

Purpose: Make the phase goal ("a game generated by `bs-build-chunk` never renders a broken `<img>`")
literally true for the AutoUI path, not just custom UI.
Output: Both renderers reveal the real image only on `load` and revert to their existing drawn
fallback on `error`; direct unit tests using synthetic `load`/`error` events (jsdom-safe).
</objective>
