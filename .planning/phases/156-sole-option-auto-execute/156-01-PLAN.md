<objective>
Close AUTOEXEC-01 (D7): when an action is the only legal option, the shell auto-*starts* it
(surfaces its beat) but never silently auto-*executes* it. Delivered as a new chainable
`ActionBuilder.manual()` flag threaded through action metadata to the shell, where the
no-selection auto-execute branch is gated on `!action.manual`.

Purpose: today a sole no-selection action (e.g. a draw) is auto-executed for the player — the
shell plays the game for them and the draw beat vanishes. This hit 3 games and is a Blocker. The
fix is at the library layer only (Phase 169 removes the per-game workarounds once this ships).

Output: `manual?: boolean` on `ActionDefinition` + a `.manual()` builder; the flag threaded through
BOTH metadata builders and typed on the metadata shape (server → wire → client); the bridge
auto-execute branch (both routes) gated; and a one-time dev-mode warning on the un-`manual()` silent
auto-execute path so the roadmap-locked default is no longer silent (Pit of Success). Net-new
RED → GREEN → adversarial coverage, since no test today asserts the sole no-selection beat is
preserved.
</objective>

<decisions>
## Locked decisions implemented here (156-CONTEXT.md)

- **manual() = auto-start-but-never-auto-execute.** Opt-in; the default for a sole no-selection action
  stays auto-execute (roadmap SC3). `manual()` only suppresses the no-selection execute branch.
- **No-op on actions with selections** — those already auto-*start* and never auto-execute; the gate is
  only on the `:278-281` no-selection branch.
- **Both routes covered.** Suppression must hold on the primary watcher AND the `actionCompletedTick`
  end-turn coalescing path — they share `tryAutoStartSingleAction`, so one gate covers both. Proven
  adversarially in Task 3.
- **Dev warning (Pit of Success resolution).** When a sole no-selection action auto-executes WITHOUT
  `manual()`, emit a one-time dev-mode-only warning naming the action and mentioning `.manual()`. Reuse
  `devWarn` (already dev-only + once-per-key). Must NOT fire in production; must NOT fire more than once
  per action. Wording is Claude's discretion but MUST name the action and mention `.manual()`, and MUST
  NOT leak file paths, line numbers, or stack traces.
- **Metadata threading is explicit, not automatic.** `undoable` is deliberately server-only; `manual` is
  the opposite — it MUST reach the client, so add the explicit line in BOTH `buildActionMetadata` and the
  followUp `buildSingleActionMetadata`. Serialize only when `true` (omit when false/absent).
- **AI seat unaffected** — `ai-controller.ts` plays a sole legal move regardless; do NOT gate the AI.
  `manual()` is a human-UI hint only.
- **Custom UI + Action Panel parity** (CLAUDE.md hard rule) — both read the same `action.manual` via the
  shared bridge; neither may auto-execute a manual action.
- **PROC-01:** the headline RED is the bridge beat-consumption test (observable: `executeAction` NOT
  called for a `manual` sole option), proven failing on the UNGATED bridge for the RIGHT reason (beat
  silently consumed), NOT a missing symbol. RED strictly before GREEN; adversarial before close.
</decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session build → wire → client bridge | `manual` metadata crosses server→client here; it is a display/interaction HINT, never an authorization signal — the server never trusts it for validity |
| client shell auto-execute | The bridge decides whether to auto-submit a sole no-selection action on the local player's behalf |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-156-01 | Tampering | A client tampering with `manual` in metadata to force/skip auto-execute | accept | `manual` is purely a client-side UX hint (auto-execute is a local convenience, not a privileged op). The server still validates every submitted action independently; toggling `manual` only changes whether the LOCAL client auto-submits — it grants no capability. No server-side trust is placed in the flag. |
| T-156-02 | Information Disclosure | Dev-warning message leaking implementation detail | mitigate | The `devWarn` message names only the action name and mentions `.manual()`; explicit prohibition on file paths, line numbers, and stack traces (project hard rule), and `devWarn` is dev-mode-only (never reaches a production console). Asserted in Task 3. |
| T-156-03 | Denial of Service (repudiation-adjacent) | Silent auto-execute deleting the player's beat (the original D7 defect) | mitigate | `.manual()` suppresses the silent execute on both routes; the un-`manual()` default is no longer silent (one-time dev warning surfaces it to the designer). Proven RED→GREEN + adversarial (Task 1–3). |
| T-156-SC | Tampering | npm/pip/cargo installs | N/A | No package installs in this phase (RESEARCH.md: thin vertical, no new libraries). No `## Package Legitimacy Audit` required. |

Most STRIDE categories (Spoofing, Elevation of Privilege) are N/A for a client-side UI-behavior flag
that carries no authority and crosses no auth boundary — stated honestly rather than padded.
