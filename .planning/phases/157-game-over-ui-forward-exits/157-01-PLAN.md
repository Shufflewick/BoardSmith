<objective>
Close ENDGAME-01 (D10): make the shell `GameOverCard` suppressable (via a `#game-over` slot and a
`providesOwnGameOverUI` prop), dismissable (close button + Escape), and correctly labeled — a genuine
draw says "Draw", winner data that is merely unavailable stays "Game Over", and it never claims a

mislabeled; there is no draw concept and no dismiss (`escapeToClose:false`, "Escape does NOT close"),
and there is no way for a game to replace the card. Three games hit this.

Output: an explicit `isDraw` signal threaded from the session (`snapshot-session-host` meta →
`multiplayer-host` game_state frame → GameShell capture → card prop), a rewritten labeling function, a
dismiss affordance, a `#game-over` scoped slot, a `providesOwnGameOverUI` prop, corrected live-region
announcement, plus net-new regression + adversarial coverage.

<decisions>
## Locked decisions implemented here (CONTEXT.md ENDGAME-01)

- **Both suppression mechanisms:** a `#game-over` scoped slot (props
  `{ winners: Player[], players: Player[], isDraw: boolean, rematch, newGame, dismiss }`) AND a
  `providesOwnGameOverUI?: boolean` prop. A filled slot auto-suppresses the default card; the prop
  suppresses BOTH the default card and the slot.
- **Dismissable:** add a close affordance (top-right, `aria-label="Close"`, ≥44×44 CSS px, tokened —
  no raw colors) and reverse `escapeToClose:false` → `true`. Dismissing hides the card and reveals the
  board; it does NOT restart or leave. Focus returns to the board region on dismiss; the trap stays
  active only while the card is shown.
- **Draw vs unknown (the mislabel fix):** drive the distinction from an explicit `isDraw` threaded off
  the session, NOT from a bare `[]`. `isDraw = isComplete && winners.length === 0`. Card headline is a
  pure function of `winners` + `isDraw` per the UI-SPEC table: 1 → "{name} wins"; >1 → "{names} win";
  `isDraw` → "Draw"; winners unavailable (isDraw false AND no winner seats) → "Game Over". The card
  MUST NOT render winner tokens when there are no winners.
- **Discretion taken:** signal name is `isDraw: boolean` (CONTEXT allows this or nullable winners);
  chose the explicit boolean because the wire frame already carries `winners: number[]` and a naive
  "empty === draw" would re-break the dev-WS degrade case (RESEARCH Pitfall). Close affordance is a
  text "×" button styled with `--bsg-ink` on transparent (UI-SPEC §2 default).
- **UI parity (CLAUDE.md hard rule):** slot + suppression must behave identically for a game using a
  custom board UI and one using the default — assert both in the GameShell test.
- No new tokens/colors; AA in light and dark; messages carry no paths/line numbers/stack traces.
</decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session host → client (game_state frame) | The `winners` / `isDraw` meta crosses the WS/postMessage bridge to the GameShell; the client must not fabricate an outcome from a partial frame |
| game code → shell (slot / prop) | A game supplies `#game-over` slot content and `providesOwnGameOverUI`; trusted (same bundle) but must not be able to leak other seats' data through slot props |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
