<objective>
Close ENDGAME-02 (D11): make every forward exit from a finished game actually restart. Route Rematch,
New Game, dev-restart, and DebugPanel restart through the ONE real restart path
(`{type:'restart'}` → `multiplayer-host.handleRestart` → `startGame()`), relax the phase guard so a
finished game can restart, and add the missing DevHost handler for the `debug:restart` postMessage.

Purpose: the real restart already exists and rebuilds the runner with a fresh seed, but three cruxes
keep the controls from reaching it (RESEARCH): (1) GameShell's Rematch posts `debug:restart`, which has
NO DevHost handler and round-trips to nothing; (2) "New Game" calls `leaveGame()` → a
nonexistent-in-dev lobby, never restarting; (3) `handleRestart` is gated `if (this.phase !== 'playing')`
(`multiplayer-host.ts:257`), so a restart from a finished game is rejected with "No game in progress to
restart." This blocks multi-game formats. Two games hit it.

Output: relaxed guard (allow `playing || complete`, still reject no-game/mid-setup), a DevHost
`debug:restart` handler routed to the working `newGame()` path, "New Game" routed to restart, plus a
host/session regression proving a finished game restarts with a fresh runner+seed and adversarial proof
that the restart truly resets state.
</objective>

## Locked decisions implemented here (CONTEXT.md ENDGAME-02)

- **One real restart path.** Route ALL forward exits (Rematch, New Game, dev-restart, DebugPanel
  restart) to `{type:'restart'}` → `handleRestart` → `startGame()`. Kill the dead `debug:restart`
  round-trip by giving DevHost the handler it always claimed to have.
- **Relax the guard** to allow restart when the game is `playing` OR complete; still reject when there
  is genuinely no game / mid-setup. Discretion (CONTEXT): the authoritative signal in
  `multiplayer-host` is `this.phase === 'playing'` + a live `this.session`; a finished game stays
  `phase==='playing'` (there is no `'complete'` phase), so relaxing to `this.phase !== 'playing' ||
  !this.session` correctly admits a finished game while still rejecting lobby/setup. Keep the actionable
  "No game in progress to restart." message for the genuine-no-game rejection.
- **DevHost `debug:restart` handler** calls the working `newGame()` path — do NOT invent a new op.
- **"New Game" restarts** (fresh seed) instead of the inert `leaveGame()`. Rematch-vs-new-settings is
  deferred to the platform/lobby (out of scope) — in dev both simply restart.
- Do NOT invent a new reset — `startGame()`/`handleRestart` already rebuild the runner with a fresh
  seed. Wire to it. Error messages stay actionable and leak no paths/line numbers/stack traces.
</decisions>
