<objective>
Close ZOOM-01 (D12): `useAutoZoom` fits the board ONCE at startup and then permanently disconnects its
only observer (which watched the board's own size, never the region or dock). So when the floating
action dock lands (dockHeight grows) or the region resizes, the fit goes stale and regions become
unreachable — three games shipped a manual Fit-button workaround for it.

Purpose: the one-shot was too aggressive, not wrong in spirit. This plan REFINES it: keep re-fitting on
**available-space** changes (dock height + region resize) for the whole component lifetime, while
preserving the two deliberate exclusions that made the one-shot desirable — never yank the zoom on
mid-game board content growth, and never fight a user who has manually zoomed.

Output: a persistent region `ResizeObserver` + `watch(dockHeight, …)` feeding a single rAF-coalesced
re-fit in `useAutoZoom.ts`, guarded by a `userControlled` flag (set by `setZoom`, cleared by
`fitZoom`), with net-new regression coverage (there is currently ZERO test driving a post-startup
dock/region change) and adversarial verification that a manual zoom survives and the content-growth
exclusion holds. PROC-01 arc: RED proven failing → GREEN → adversarial.
</objective>

<decisions>
## Locked decisions implemented here (from 158-CONTEXT.md)

- **Re-fit trigger = available-space only.** A persistent `ResizeObserver` on `regionEl` + a
  `watch(dockHeight, …)`. NOT the board's own size. The board-content-growth exclusion is preserved:
  after startup the board is no longer observed, so its growth triggers nothing.
- **Observers live for the component lifetime.** Stop the permanent disconnect-after-settle of ALL
  observation. The board-settle startup logic MAY remain for the FIRST fit (Claude's discretion —
  keep it if the initial fit still works); what must change is that region/dock observation is not
  torn down at `endStartup()`. Tear down on scope dispose (`onUnmounted`/`onBeforeUnmount`).
- **rAF-coalesce** re-fits: a cascade of dock+region changes yields ONE `measureAndFit()`, not thrash.
  Also do an rAF re-measure on wiring to catch iframe/host resize RO may miss
  (`useBoardSize.ts:83-85` precedent).
- **Manual-zoom guard (`userControlled`):** `setZoom` sets it true → the region-obs / dock-watch
  re-fit path no-ops (user zoom wins). `fitZoom()` clears it and re-fits (re-arm). A player who never
  calls `setZoom` gets continuous auto-refit. Do NOT add any force-refit that overrides a user zoom —
  reachability under a manual zoom is already guaranteed by the scrollable region
  (`margin-bottom: var(--dock-h)`).
- **No new shared composable.** One-up a local RO with teardown, following `useBoardSize`. (The
  shared `useResizeObserver` unification is a deferred idea, not this fix.)
- Any warning/comment must be actionable and leak no internal paths/line numbers (project hard rule).
  Update the file header comment: it currently says "stops for good" / "Mid-game content growth,
  window resizes, etc. never move the zoom" — that is now only true for board CONTENT; available-space
  changes DO re-fit. Correct the comment so it does not lie.

## Claude's discretion (per CONTEXT)
- Whether the region-obs and dock-watch share one `scheduleRefit()` scheduler or are separate (prefer
  shared — it is the natural coalescing point).
- The exact rAF-coalescing implementation and the name/scope of the `userControlled` flag.
- Whether to keep the startup-settle path as-is alongside the persistent path, or fold them.
</decisions>
