<objective>
Close the browser-side half of DEVHOST-01 (D13): a human-facing selector in the dev-host lobby for the
game's declared `gameOptions` and `presets`, wired to the host selection message Plan 02 introduced.

Purpose: Plan 02 gave the host a way to receive a selection and flow it into the start op, and exposed
`gameOptions`/`presets` on `DevHostConfig`. But `DevHost.vue`'s Table-setup is read-only
(`:644-682`) and the lobby claim area (`:482-508`) only offers name + color — there is no way for a
human to pick a gameOption or preset. This plan adds that selector.

Output: a lobby gameOption/preset selector reusing the existing `--bsg-*` styling of the claim area,
whose apply handler sends the host selection message so the chosen values reach the start op; selecting
a preset fills the option selectors with its bundle. Covered by a `FakeWebSocket` DevHost test.
</objective>

<decisions>
## Locked decisions implemented here (CONTEXT.md D13)

- **Selector lives in the lobby claim area**, reusing the existing `--bsg-*` styling — this is a
  selector, NOT a lobby redesign (CONTEXT deferred idea #2 is out of scope).
- **Reads declared options/presets from `DevHostConfig`** (`cfg.gameOptions`, `cfg.presets`) — no
  re-derivation.
- **A preset fills the option selectors** with its bundle of values (selecting a preset is a shortcut
  for setting the underlying options); apply then sends the resolved selection to the host.
- **The host validates** (Plan 02, T-161-02) — the selector only OFFERS declared options/values, and
  relies on the host as the authoritative gate. Do NOT duplicate authorization in the client.
- **Claude's Discretion (CONTEXT):** the exact selector markup (dropdowns vs. segmented controls) and
  where the Apply/restart affordance sits — provided it reuses the claim area's tokens.
</decisions>
