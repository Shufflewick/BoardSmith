<objective>
Close TOOL-03 (D19, Blocking) and TOOL-04 (D20): make `boardsmith/ui` import side-effect-free under
jsdom, and make `assertNoHiddenInfoLeak` usable for symmetric decks by keying leak detection on
element identity rather than a bare name-string substring.

Purpose: `useElementAnimation.ts` reads `window.matchMedia(...)` in a module-scope ref initializer
(`:36-40`) and registers a `change` listener at module scope (`:43-48`). The guard is
`typeof window !== 'undefined'` — jsdom HAS `window` but NOT `matchMedia`, so importing the
`boardsmith/ui` barrel throws unless every game test pre-stubs matchMedia (D19, Blocking — games
can't test UI under jsdom without the shim). Separately, `assertNoHiddenInfoLeak` derives forbidden
markers carrying `elementId` but matches them by pure `surface.includes(marker.value)`
(`dom-leak.ts:497`), so two identical-named cards are indistinguishable: a hidden card A and a
legitimately-visible same-named card B collide, producing a false positive (or masking a real leak).

Output: a guarded, lazily-initialized reduced-motion accessor that runs nothing at import; an
elementId-keyed surface match that distinguishes symmetric-deck siblings; and RED-first regression
coverage for both, with every existing dom-leak and UI test still green.
</objective>

<decisions>
## Locked decisions implemented here

- **D19:** Make `useElementAnimation.ts` import side-effect-free. Guard on
  `typeof window.matchMedia === 'function'` (NOT just `typeof window !== 'undefined'`) AND defer the
  `matchMedia` read + `addEventListener` out of module scope into a lazy getter/initializer so
  NOTHING executes at import. Importing `boardsmith/ui` under jsdom with no shim must not throw.
  Preserve the reactive reduced-motion behavior for real consumers — `prefersReducedMotion` stays a
  reactive `Ref<boolean>` that updates on the OS `change` event once initialized. Discretion: a
  lazily-initialized ref vs an accessor function, provided reactivity is unchanged and import is
  side-effect-free.
- **D20:** Key detection on the marker's `elementId` / element identity, not the bare name-string
  substring. Attribute each scoped surface string to its owning element (nearest `data-element-id`
  ancestor); a marker for hidden element X matches only surfaces owned by X's own id — so a visible
  same-named sibling Y (its own id) no longer trips X's marker. Surfaces with no owning
  `data-element-id` (can't be attributed) are checked conservatively against all markers so a leak
  in an un-attributed surface is never silently dropped. Discretion: per-element region vs global id
  set, provided symmetric-deck siblings are distinguishable and ALL existing cases pass.
- Do NOT remove the ~15 defensive `matchMedia` stubs in existing UI tests this phase (deferred
  cleanup) — the fix only makes them unnecessary; they must keep working.
</decisions>
