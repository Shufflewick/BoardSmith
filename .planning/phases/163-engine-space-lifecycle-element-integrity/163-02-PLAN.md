<objective>
Close SPACE-03 (D24): a hidden `Space` leaks its exact child count to opponents through the serializer.
Today `toJSONForPlayer`'s zone branch (`game.ts:2867-2901`) handles `'hidden'` and `'count-only'`
IDENTICALLY — both emit `childCount` and a full array of anonymized per-child placeholders. That means
a `'hidden'` deck/hand tells every opponent EXACTLY how many cards it holds, which is precisely the
information `'hidden'` is supposed to conceal. Games have been faking real concealment by hiding each
child individually (the `concealFromEverySeat` smell); this fix makes that workaround unnecessary
(its removal is Phase 169, not here).

Purpose: `'hidden'` must mean "you learn nothing"; `'count-only'` must mean "you learn the count and
nothing else" (its defined purpose — keep it). The fix is a narrow split of one branch by mode.

Output: a mode-gated `toJSONForPlayer` branch + net-new regression proving `'hidden'` emits no count
while `'count-only'` still does, with Phase 159's redaction guarantees held intact.
</objective>

<decisions>
## Locked decisions implemented here (D24)

- **`'hidden'` emits NEITHER `childCount` NOR per-child placeholders** — true concealment. The
  container returns its own (whitelist-redacted `ownJson`) attributes only, with NO `children` and NO
  `childCount` key at all (not `childCount: 0` — absent, so a viewer cannot even distinguish empty from
  full).
- **`'count-only'` keeps `childCount` AND the anonymized placeholders** — that is its defined purpose;
  do NOT regress it.
- **Do NOT regress Phase 159** — negative synthetic ids, `__hidden`, `redactHiddenElementAttrs`, and the
  `idRemap` relink stay exactly as-is on the `'count-only'` path. Only the COUNT (and placeholder array)
  is suppressed for `'hidden'`. `image-leak` / `zone-visibility-restore` must stay green.
- The `'hidden'` path does not populate `idRemap` (there are no synthetic child ids to relink because
  no placeholders are emitted) — confirm no restore relies on hidden-mode remap entries.
</decisions>
