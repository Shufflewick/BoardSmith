<objective>
Build the deterministic half of the ingest verification harness: a checker that reads a project
directory produced by a real `/bs-ingest-rules` run and reports, per named check, whether the
INGEST-01/02/03/04 contract actually landed in the produced artifacts.

Purpose: the 2026-07-27 proof run failed 7 of 9 checks after three skill-text fixes that every
contract test called green. `170-PROOF-RUN.md`'s conclusion is the premise of this plan: **a
contract test proves an instruction exists; it cannot prove an agent receives or follows it.**
Reaching that finding cost three human ingest sessions. This checker makes the next iteration cost
an agent instead — and, because it is exercised against the actual failed output, it is provably
capable of catching the defect that shipped.

**Determinism and CI placement — the decision, stated up front.** This plan splits the harness in
two on purpose:

- **This plan's half is deterministic and belongs in CI.** `check.mjs` is a pure filesystem +
  string function. Its self-test reads two checked-in fixture trees, invokes no agent, and lands
  under `scripts/**/*.test.mjs`, which `vitest.config.ts` already includes — so it runs inside
  `npm test` alongside the existing 3211 tests without making any of them non-deterministic.
- **The live-agent driver is NOT in CI** and is built separately in Plan 06 as an
  operator/agent-invoked script. LLM output varies run to run; putting a live ingest session into
  the default suite would make every commit non-deterministic and slow. That decision is Plan 06's
  to state and honor; this plan simply keeps the two halves in separate files so the boundary is
  structural rather than a convention someone can forget.

**What is NOT proven by this plan.** A green checker self-test proves the checker works. It proves
nothing about the skill text. No INGEST requirement is closed here.

Output: `check.mjs`, two fixture project trees, and a self-test that is RED against the real failed
run and GREEN against a conforming tree.
</objective>

Create `scripts/ingest-harness/check.mjs` as an ESM module exporting `checkIngestArtifacts` and
`CHECK_IDS` with the signature given in `<interfaces>` above. Import only `node:fs`, `node:path`,
and `node:crypto` — no new dependency, matching the repo's zero-new-dep posture for this phase.

The function reads `{projectDir}/rulebook/` and returns one result object per check id, always all
nine, always in `CHECK_IDS` order, each carrying `pass` plus a `detail` string that states the
observed value — never a bare boolean. A check that cannot run because an upstream file is missing
reports `pass: false` with a detail naming the missing path; it never throws and never silently
skips. Top-level `pass` is the AND of all nine.

Define "slice files" once, as a helper, and use that definition everywhere below: every
`{projectDir}/rulebook/*.md` EXCEPT `INDEX.md` and `00-visual-survey.md`. `INDEX.md` is the index,
not a slice; `00-visual-survey.md` is by design entirely presentation description, so counting its
lines would make the `visual-lines` check trivially passable and the `derived-purity` check
trivially failable. State that exclusion in a comment at the helper.

Implement the nine checks:

- `archive-exists` (a): `{projectDir}/rulebook/source/{sourceFileName}` exists and is a regular
  file. Detail reports the resolved path and byte size.
- `archive-hash` (b): SHA-256 of that file, computed with `node:crypto` `createHash('sha256')` over
  the raw bytes, equals `expectedSourceHash` compared case-insensitively. Detail reports both
  values.
- `hash-recorded` (c): `rulebook/INDEX.md` contains a line matching a `Source hash:` label followed
  by exactly 64 lowercase hex characters and nothing else, anchored to line start with the
  multiline flag; and that captured value equals the hash actually computed in (b). Detail reports
  the captured value or states the line was absent. Comparing against the computed hash rather than
  against the expected constant is the point — it catches an INDEX that records a hash nobody ran.
- `header-block` (d): `rulebook/INDEX.md` contains, each at line start, the four labels `Edition:`,
  `Source:`, `Source hash:`, `Transcribed:`; each has a non-empty value after the label; they occur
  in that order (compare the four match indices); the `Source:` value begins with
  `rulebook/source/` and does not begin with `/` or `~` (an in-project archived path, never an
  external absolute path); and the `Transcribed:` value starts with an ISO date of the form
  four-digits hyphen two-digits hyphen two-digits. Detail names every label that failed and why.
  Additionally: if the `Edition:` value is exactly `unpublished — designer statement` while a
  `rulebook/source/` directory exists, fail with a detail naming this as the interview-path wording
  emitted on the rulebook path — that is the exact (d) defect the proof run recorded, and it is
  invisible to a bare presence check.
- `gaps-heading` (e1): `rulebook/INDEX.md` contains a line exactly equal to `## Open Rules Gaps`,
  and does NOT contain the substring `## Open Rules Gaps (`. Detail reports the actual gaps-shaped
  heading found, if any — the proof run emitted `## Open Questions (deferred at ingest by the
  designer)`, so reporting what was found instead is what makes a failure diagnosable.
- `gaps-reconciliation` (e2): count the entries in the `## Open Rules Gaps` section body (the lines
  between that heading and the next line starting with `## `, or end of file) and count every
  occurrence of `Named-but-undefined` across the slice files. An entry is a line matching a leading
  ordered-list marker (digits, then a period or close-paren, then whitespace). The two counts must
  be EQUAL. The single exception, and the only one: a body whose sole non-blank, non-note line is
  exactly `_None._` passes if and only if the slice-side count is also 0. Run this comparison
  unconditionally, for every entry count — never gate it on the count looking low; a drop can land
  anywhere. Detail always reports both numbers, in both directions, with a note saying which
  direction was violated: markers greater than entries means the transport is dropping gaps;
  entries greater than markers means the section is not built purely from `openGaps[]`.
- `tables-intact` (f): `rulebook/INDEX.md` contains a line exactly equal to `## Slices` and a line
  exactly equal to `## Term → Slice` (with the Unicode rightwards arrow, U+2192 — not `->`). Detail
  reports which was missing and what heading was found in its place.
- `visual-lines` (h): across the slice files, at least one line matching a `Visual (p.` prefix at
  line start with a page number, and at least one matching `Derived (p.` the same way. Detail
  reports both counts per file and the totals. Zero `Visual (p.` lines is a FAIL — no waiver is
  encoded here; a waiver, if ever justified, is a human judgment made at the Plan 10 gate, not
  something the checker can grant itself.
- `derived-purity` (i): FAIL if any `Derived (p.` line in a slice file matches the presentation
  lexicon — case-insensitive alternation over: `sans-serif`, `serif`, `typograph`, `full-bleed`,
  `palette`, `wordmark`, `italic`, `font`, `aspect ratio`, `illustration`, `iconograph`, `art
  style`, `rotated`, `bold white`, `depicted`. Detail lists every offending file, line number, and
  the matched token. Comment at this check, in the source, that it is a **heuristic**: it can
  produce a false positive on a genuinely rule-bearing line that happens to mention a component's
  appearance, and the Plan 10 human gate adjudicates such a case. It exists because the proof run's
  two clearest misfilings (`02-solo-variant.md:21` and `01-components-and-credits.md:30`) both trip
  it, so it demonstrably catches the real defect rather than an imagined one.

Export `CHECK_IDS` as a frozen array so Plan 06's driver and Plan 08's addition both order their
output from one source of truth rather than restating the list.
