<objective>
Build the live-agent half of the harness: a driver that stages a throwaway project, installs this
repo's current skill text into it, runs a real `/bs-ingest-rules` session headlessly against a real
rulebook PDF, and reports Plan 05's nine checks — then prove it by running it once against current
HEAD and confirming it reproduces the human gate's failures.

Purpose: `170-PROOF-RUN.md` records that three human ingest sessions were spent discovering that the
orchestrator does not execute its skill text literally. Every remaining plan in this phase changes
skill text and must be verified against live agent behavior, because that is the only place the
defect appears. Without this driver, each of those verifications costs another human session.

**Determinism and CI placement — the decision and its justification.** This driver is
**operator/agent-invoked only, never in CI**, exposed as `npm run harness:ingest`. Three reasons,
all load-bearing:

1. LLM output varies run to run. The repo runs 3211 tests on every commit and they must stay
   deterministic; a flaky live-agent test would be quarantined within a week and then ignored.
2. A real ingest session costs real tokens and minutes. CI cost per commit is the wrong place to
   pay it.
3. The determinism that CI *should* pin already exists: Plan 05's `check.test.mjs` pins the
   checker's judgment against static fixtures and does run in `npm test`. What varies is the agent
   run; what is invariant is the checker. Splitting them is what lets each be tested honestly.

The rule this creates, and the one every later plan in this phase follows: a skill-text change is
not verified by a green contract test. It is verified by `npm run harness:ingest` reporting the
relevant check green. Contract tests remain as fast regression pins — they catch a reword that
deletes a required string — but they are explicitly **not** the acceptance bar, because every one of
them was green on 2026-07-27 while all four INGEST requirements failed.

**What is NOT proven by this plan.** The baseline run is expected to FAIL. A failing baseline is the
success condition here: it demonstrates the harness reproduces the known defect. No INGEST
requirement is closed.

Output: `run.mjs`, an npm script, and a recorded baseline run.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness driver to the operator's global `~/.claude/skills/` | The driver installs skill text; a non-`--local` install would overwrite the operator's working skill tree mid-development. |
| harness driver to `~/BoardSmithGames/seven` | The driven agent reads the designer's rulebook and must never write to that repo. |
| headless agent with permissions bypassed | `--dangerously-skip-permissions` gives the driven session unattended tool access. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-170-15 | Tampering | operator's global skill tree | mitigate | Install is `--local` into `{workDir}` only; `stage` asserts no `~/.claude/skills` entry has an mtime newer than process start and prints that assertion |
| T-170-16 | Tampering | `~/BoardSmithGames/seven` | mitigate | `stage` hard-stops on a dirty tree or a hash mismatch; `assert` re-checks `status --porcelain` and `rev-parse HEAD` against the recorded baseline as gate item (g) |
| T-170-17 | Elevation of Privilege | headless session with permission checks bypassed | mitigate | cwd is a freshly recreated `/tmp` tree; `--add-dir` grants exactly one additional path (the rulebook's directory); the repo working tree is never the session's cwd |
| T-170-18 | Denial of Service | CI runtime and determinism | mitigate | The driver is absent from `npm test` and cannot match any `vitest.config.ts` include pattern; acceptance asserts both |
| T-170-SC | Tampering | npm/pip/cargo installs | accept | No package installs; `node:` builtins and the already-present `claude` CLI only |

Medium severity on T-170-17: unattended permission bypass is a real capability, bounded here to a
