<objective>
Replace the prose that describes `rulebook/INDEX.md` with a template the orchestrator copies and
fills, and promote the source archive + hash from a sub-item buried in an eight-item list to its own
numbered step — then prove both against a live harness run.

Purpose: `170-PROOF-RUN.md`'s Experiment 2 is the whole argument. In one session, the same
orchestrator produced an `ASSETS.md` that matched `templates/ASSETS.template.md` exactly — heading,
`## Ledger`, five-column header, verbatim — while producing an `INDEX.md` that diverged from its
prose spec on **every specified string**. `rulebook/INDEX.md` is the only artifact in this pipeline
with no template; `SKETCH`, `CHUNK`, `ASSETS`, `DECISIONS`, `DESIGN`, and `RULINGS` all have one and
all come out conforming. The mechanism that survives this orchestrator is structural. This plan
gives `INDEX.md` the same structure the artifacts that work already have.

The archive+hash step gets the parallel treatment for the same reason: it was landed by Plan 02 as
item 1 of an eight-item Step 3 list, and the live run never created `rulebook/source/` at all —
failing gate items (a), (b), and (c) together. A separate numbered step with a single deliverable is
harder to skip than a paragraph inside a list about assembling six other things.

Three defects the template is designed to fix directly, each observed in the failed run:
- `Source hash:` and `Transcribed:` were absent entirely. A template line cannot be absent from a
  copied file; it can only be left unfilled, which the harness detects as an empty value.
- `Edition:` read `unpublished — designer statement` — the **interview-path** wording emitted on the
  **rulebook** path. The template's Edition line carries an inline fill instruction naming which
  path each allowed value belongs to.
- The gaps heading came out as `## Open Questions (deferred at ingest by the designer)` and the
  tables as `## Slice Manifest` / `## Term Cross-Reference`. Those four headings are literal text in
  the template, so producing them correctly requires no compliance at all — only copying.

**Acceptance bar.** The contract tests added here are fast regression pins that catch a reword
deleting a required string. They are **not** the acceptance bar, and saying so is not a formality:
every contract test in this phase was green on 2026-07-27 while all four INGEST requirements failed
their real run. This plan is accepted when `npm run harness:ingest` reports `archive-exists`,
`archive-hash`, `hash-recorded`, `header-block`, `gaps-heading`, `gaps-reconciliation`, and
`tables-intact` all PASS against a live agent run.

**What is NOT proven here.** `visual-lines` and `derived-purity` are INGEST-02 and belong to Plan 08.
This plan does not close INGEST-02 and must not claim to.
</objective>
