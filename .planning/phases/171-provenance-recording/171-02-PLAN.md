<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → provenance claim | file bytes outside the project (the installed skills tree, package.json) are hashed into a record that later gates a verification claim |
| project dir → home dir | `resolveSkillsRoot` may read `~/.claude/skills`, outside the project being recorded |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-171-04 | Spoofing | provenance version field | mitigate | `readBoardsmithVersion` throws rather than returning a fallback, so a block can never carry an invented version |
| T-171-05 | Tampering | skills-tree hash coverage | mitigate | Path is hashed alongside content and entries are sorted, so a moved or reordered file cannot produce a colliding "unchanged" hash |
| T-171-06 | Information disclosure | reading `~/.claude/skills` | accept | Only a digest is recorded, never file contents or the absolute root path; the CLI is run locally by the designer who owns both trees |
| T-171-07 | Denial of service | walking a very large `.claude/skills` tree | accept | Bounded to `bs-`-prefixed entries the installer itself created (5 skill dirs + bs-shared) |
| T-171-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed; `git diff package.json` empty is an acceptance criterion |
</threat_model>
