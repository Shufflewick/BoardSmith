    - `Claim 7` (capitalised) → claims [7]

    - `claim 28 / Ruling 9/15` → claims [28], rulings [9,15]
    - `Ruling 23`, `rulings 21/22` → rulings [23] and [21,22]
    - `importsRules` is true when the file imports from a `src/rules/` path (any relative or
      aliased form resolving to `src/rules/`), false for a file importing only engine/testing
      packages.

    resolveClaimCitation(claimNumber, owners, liveClaims, authoring) — the ladder, each rung
    exercised as the DECIDING one:
    - Rung 1 alone: exactly one owner → resolves to it.
    - Rung 2 deciding: 3 owners, only one of which lists claim N in its live Interpretation set →
      resolves to that one. (This is the common real case: claim counts range 0–77 and 4/17 seven
      chunks number non-contiguously, so validity discriminates hard.)
    - Rung 3 deciding: 2 owners both listing claim N, one manifest row marks the file NEW/written
      and the other `edited` → resolves to the authoring chunk.
    - Ambiguous: 2 owners both listing claim N and both marked authoring → `ambiguous-claim-ref`
      naming both survivors, counting as coverage for NEITHER.
    - Zero owners → unresolved (the caller pairs this with `unassociated-test`).
    - All owners discarded at rung 2 (no owner has a live claim N) → unresolved, stale-citation
      sense: a test citing `claim 40` where every owning chunk's list stops at 35.
    - No proximity, filename-slug, or most-recent-chunk heuristic exists anywhere in the function.
  </behavior>
  <action>
Create `src/cli/commands/trace-check.ts`. Start with the two pure functions; the command action
comes in task 2.

`scanTestCitations(sourceText)` returns `{ claims: number[]; rulings: number[]; importsRules: boolean }`,
line-wise over the source so a citation's line number stays recoverable if needed. Match a claim
citation head (`claims?` case-insensitively) followed by a number list separated by commas,
slashes, `and`, or whitespace — and STOP the number list at a `Ruling` token so
`claim 28 / Ruling 9/15` splits correctly rather than swallowing 9 and 15 as claims. Match ruling
citations the same way with a `rulings?` head. Ignore any `CHUNK.md ` prefix. De-duplicate.

`resolveClaimCitation(claimNumber, owners, liveClaims, authoring)` implements CONTEXT.md decision 3
verbatim, and its doc comment must state the ladder and cite decision 3, including the residual
risk the user accepted at rung 3 (a claim added by a later editing chunk attributes to the
authoring chunk; rung 2 removes most of that exposure). Return a discriminated result:
`{ status: 'resolved', chunk }`, `{ status: 'ambiguous', candidates }`, or
`{ status: 'unresolved', reason: 'no-owner' | 'no-live-claim' }`.

Implement it as literally three sequential narrowing steps over a candidate array, in this order,
with no early cleverness:
  1. candidates = owners (chunks whose Build Manifest lists this test file);
  2. filter to candidates whose live claim set contains `claimNumber`;
  3. if more than one survives, filter to candidates whose manifest row for this file is `authoring`.
Report `ambiguous` only if more than one survives step 3. If step 2 empties the set, return
`no-live-claim`; if step 1 was empty, return `no-owner`. If step 3 empties a non-empty step-2 set
(no candidate is authoring), the step-2 survivors remain the candidates and the result is
`ambiguous` — narrowing must never discard every survivor and report nothing.

RESEARCH.md's § Validation Architecture row 2 states an OLDER resolution rule
("1 owner=resolved, 0=unassociated, 2+=ambiguous") — that is SUPERSEDED by CONTEXT.md decision 3's
amendment and must not be implemented. RESEARCH.md's predicted finding counts (~67 ambiguous on
one-two-punch, claim-untested approaching 165/212) were computed under the old rule and are now
UPPER BOUNDS only; assert no such number in any test.

Write the tests as table-driven cases, one per behavior bullet, with a fixture builder that
constructs the `owners`/`liveClaims`/`authoring` inputs explicitly so each rung's deciding case is
readable at a glance.

  <behavior>
    - Enumerates `chunks/*/CHUNK.md`, building per chunk: live claim set (parseInterpretationClaims)
      and manifest entries (parseBuildManifest). A `chunks/<slug>` directory with no CHUNK.md is
      skipped silently, matching `chunkProvenanceStatusCommand`.
    - Builds the file → owning-chunks index from manifest entries; the same test file listed by
      several chunks yields several owners.
    - Scans every `*.test.ts` under `tests/` (and any test file named in a manifest) for citations.
    - `unassociated-test`: a scanned test file in no chunk's manifest. Its claim refs are ALSO
      emitted as `unresolved-claim-ref` — one finding per ref, never silently dropped (decision 2).
    - `unresolved-claim-ref` (stale-citation sense): a citation whose owners all lack a live claim
      with that number; `detail` names the citing file and the owners checked.
    - `ambiguous-claim-ref`: `subject` is the claim number and citing file; `detail` names every
      surviving candidate chunk.
    - `claim-untested`: every live claim in a chunk with zero citations RESOLVED to that chunk.
      An ambiguous citation counts as coverage for none of its candidates, so it does not suppress
      this finding.
    - `ruling-untested`: a `### Ruling N` entry cited by no test file anywhere (ruling numbering is
      global, not per-chunk). A ruling with `supersededBy` set is NOT reported. `chunk` is the
      empty string or `RULINGS.md` — rulings are not chunk-scoped.
    - A ruling citation in an `unassociated-test` file still counts toward ruling coverage — ruling
      numbers are global, so file ownership is irrelevant to them (real case: seven's
      `match.a11y.test.ts`).
    - `test-unlinked` (decision 6b) fires ONLY when all three hold: the file IS listed in ≥1
      manifest, AND it imports from `src/rules/`, AND it cites neither a claim nor a ruling. It
      does NOT fire for an a11y/theme/asset-reachability/soak file that imports no rules layer, and
      does NOT fire for an unassociated file (already covered by `unassociated-test`).
    - `manifest-file-missing`: a manifest row yielding zero path tokens (`detail`: "row N has no
      path token"), and separately a `## Build Manifest` that is not table-shaped (`detail`:
      "manifest is not table-shaped"). The two are distinguishable by `detail` alone — no tenth
      finding kind is added.
    - `unparsedSupersessions` from `parseRulings` are carried into the result and printed, so an
      unparseable chain is reported rather than assumed either way.
    - No RULINGS.md → zero ruling findings, zero crash; the claim half still reports.
    - Never runs `npm test`, never imports the engine, never reads `rulebook/` (decision 4 —
      source-free by construction, not by flag).
    - READ-ONLY: a whole-project byte-hash taken before and after a run against a fixture project
      is identical (the T-171-19 test class).
  </behavior>
