    - `diffedFilesSince(repoDir, <first commit sha>)` returns exactly the files changed by the

    - A file deleted in the second commit appears in the returned list.
    - The command runs git with `cwd` = the passed project directory. A test asserts this directly
      by running against a temp repo whose HEAD differs from BoardSmith's own: the returned file
      list matches the temp repo's history, proving the diff did not run against BoardSmith.
      (Pitfall 3: a test that passes without ever creating a `.git` directory is not exercising
      this code path at all.)
    - A syntactically valid but unresolvable hash returns the `unresolvable` sentinel rather than
      throwing.
    - A hash-shaped string that is NOT `/^[0-9a-f]{7,40}$/` — notably one starting with `-`, e.g.
      `--upload-pack=touch /tmp/pwned` pasted into a hand-edited `## Verified Commit Hash` — is
      rejected BEFORE any git invocation and returns the `unresolvable` sentinel. git is never
      called with it.
    - A project directory that is not a git repo makes the COMMAND throw an actionable one-line
      error (tool failure, decision 6), not report a finding.
  </behavior>
  <action>
Create `src/cli/commands/drift-check.ts` and implement the git layer first.

`diffedFilesSince(projectDir, hash)` uses `promisify(execFile)` from `node:child_process` with
argv-array form: `'git', ['diff', '--name-only', hash, 'HEAD'], { cwd: projectDir }`. Never `exec`
or `execSync` with a shell string — `init.ts` uses `execSync`, and that is deliberately NOT the
pattern to copy here, because the hash comes from a hand-editable CHUNK.md.

Before invoking git, validate the hash against `/^[0-9a-f]{7,40}$/` and return the unresolvable
sentinel if it fails. `execFile` already prevents shell interpretation, but an argv element
beginning with `-` is still read by git as a FLAG — the regex is what closes argument injection
(threat T-172-01). Record that reasoning in a comment; it is the non-obvious half.

`cwd` is mandatory on every git invocation and is always
`resolve(options.project ?? process.cwd())` — the same value every other command in this family
resolves (`chunk-provenance.ts:709`). Add a preflight `git rev-parse --show-toplevel` in the command
and compare its result to `projectDir`'s repository root; if git is not available or the directory
is not a repo, throw an actionable error naming the directory and the `--project` flag. This is the
first command in the codebase to query git, so it sets the convention: state that in a comment
above the helper, since Phase 173 will copy it.

Tests: build a real temp git repo (`git init`, write files, `git add -A`,
`git -c user.email=t@t -c user.name=t commit`), capture the first commit's sha with
`git rev-parse HEAD`, make a second commit that modifies one file and deletes another, then assert
`diffedFilesSince` against real `git diff --name-only` output. Sandbox environments have no
configured git identity — use the `-c user.email=... -c user.name=...` form, not global config.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CHUNK.md `## Verified Commit Hash` → git argv | a hand-editable file supplies a string that becomes a git command-line argument |
| manifest-supplied path → filesystem `stat` | a manifest first cell can name any path string, including one escaping the project root |
| BoardSmith repo ↔ game repo | the subprocess must run in the game repo; the wrong `cwd` silently diffs the wrong repository |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-172-01 | Tampering / Elevation | `diffedFilesSince` git argv | mitigate | `execFile` with an argv array (never `exec`/`execSync` with a shell string), PLUS a `/^[0-9a-f]{7,40}$/` validation before invocation so a flag-shaped value such as `--upload-pack=...` can never reach git as an option. Task 1. |
| T-172-03 | Tampering | git `cwd` | mitigate | `cwd` is mandatory and always the resolved game `projectDir`; a `git rev-parse --show-toplevel` preflight confirms the directory is a repo and reports an actionable error if not. Prevents silently diffing BoardSmith's own history. Task 1. |
| T-172-02 | Information disclosure | manifest path → `fs.stat` | mitigate | Resolve each manifest path against `projectDir` and require containment; a path that escapes is reported `manifest-file-missing` and never `stat`ed. Task 2. |
| T-172-05 | Information disclosure | tool-failure error messages | mitigate | Throw a one-line actionable `Error`; `cli.ts`'s top-level catch prints `err.message` only — no stack trace, no internal path. Task 1/2. |
| T-172-06 | Tampering | read-only invariant | mitigate | No mutating `fs` call and no mutating git subcommand — only `diff`, `rev-parse`, `merge-base`. Pinned by a before/after whole-project byte-hash test. Task 2. |
| T-172-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages this phase; no install task exists. |
