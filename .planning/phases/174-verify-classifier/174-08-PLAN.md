Real `## Interpretation` claim citations carry three anchor shapes, all in one line per claim:

```
4. **The second set is resolved by the SAME procedure as the first**: ... — cites rulebook/02,
Fight-phase continuation under REST (p.2): "compare and resolve the second action cards just like
you did with the first action cards"; and rulebook/01-setup-and-round-structure.md, "2) Fight"
(p.1): "You and your opponent must flip your first action card face up at the same time and compare
their timings to determine the order they are resolved." / "The player with the lower timing ..."
```

So: (i) a slice token, full (`rulebook/01-setup-and-round-structure.md`) or shorthand (`rulebook/02`);
(ii) a page reference `(p.N)`; (iii) one or more verbatim double-quoted rulebook fragments.

Measured anchor availability across every real chunk (claims = `^N. **` items inside
`## Interpretation` only):

| Game | chunks | claims with a `rulebook/` token | claims with `(p.N)` | claims with a `"quoted"` fragment |
|---|---|---|---|---|
| `one-two-punch` | 12 | 8 chunks have ≥1 (e.g. `jab` 22/25, `setup-opening-discards` 13/17); `block` 3/23, `punch` 3/35, `ai-opponent` 0/1 | similar distribution | ≥1 in 10 of 12 chunks |
| `seven` | 17 | **many chunks have ZERO** (`best-seven-selection` 0/13, `scoring-declaration` 0/15, `scoring-run-of-7` 0/12) | mostly zero on those same chunks | present on most (`simultaneous-round-loop` 27/36, `discard` 16/19) — quotes are the anchor `seven` actually carries |

Two consequences the design must absorb rather than assume away:
1. **Quoted fragments are the load-bearing anchor, not slice tokens** — on `seven`, many claims quote
   the rulebook verbatim while naming no `rulebook/` path at all. A fragment found verbatim in a live
   slice's text attributes to that slice on its own; do not require a co-located slice token.
2. **A material number of (chunk, slice) pairs will carry NO claim-level anchor at all.** That is the
   fallback rung's whole reason for existing, and why it must broaden to decision 18's slice-level
   answer and report — never silently clean, and never silently broader than today either.

Delta-side anchor, for the two real findings this plan re-measures against:
- `seven` / `sharper` — `quotedPass1` is the whole live line
  `Named-but-undefined (p.1): bonus point cards (depicted as a black "+1" card; the text does not
  define its scoring effect beyond Game End's instruction to add bonus point cards to your score)`,
  which is line 23 of `rulebook/01-definitions-and-components.md`.
- `one-two-punch` / `contradictory` — `quotedPass1` is

3. `export interface ClaimCitationAnchors { slices: string[]; pages: number[]; fragments: string[] }`
   and `export function parseClaimCitationAnchors(chunkText: string, sliceFilenames: string[]): ClaimCitationAnchors`.
   - Body comes from `extractSection(chunkText, '## Interpretation')` (imported from `./build-manifest.js`);

   line of `sliceText` containing `quote` (first match; whitespace-normalized comparison so a
   re-wrapped quote still lands), `undefined` when absent.

5. `export function citedPageForLine(sliceText: string, line: string): number | undefined` — the page
   for a live line: a `(p.N)`/`p.N` on the line itself wins; otherwise the nearest preceding
   `p.N,` citation header (the `CITATION_HEADER_RE` shape already in this file); otherwise `undefined`.

6. `export interface CitationAttribution { attributed: boolean; rung: CitationAnchorRung; reason: string }`
   and `export function resolveCitationAttribution(input: { liveSlice: string; liveSliceText: string; deltaLine: string; deltaLinePage: number | undefined; anchors: ClaimCitationAnchors }): CitationAttribution`.

   The ladder — deterministic, three rungs, modelled on 172 decision 3's ladder, no heuristics and
   no proximity guessing:
   - **Rung `quoted-fragment`:** the chunk's fragments that occur verbatim (whitespace-normalized) in
     `liveSliceText`, OR are carried on a claim naming this slice, form this slice's fragment set. If
     that set is non-empty, `attributed` = "some fragment overlaps `deltaLine`" (containment either
     direction, whitespace-normalized). This rung DECIDES — a non-empty fragment set that does not
     overlap returns `attributed: false` with a reason naming the non-overlap. This is the narrowing
     decision 19 asks for, and the reason string is what makes a clean chunk's cleanliness nameable.
   - **Rung `cited-page`:** only when this slice's fragment set is empty and `anchors.pages` is
     non-empty and `deltaLinePage` is known — `attributed` = `anchors.pages.includes(deltaLinePage)`.
   - **Rung `slice-fallback`:** neither anchor kind is usable → `attributed: true`, reason states the
     citation could not be resolved to a claim-level anchor so decision 18's slice-level attribution
     stands. **This rung is never `false`.** A finer key has strictly more ways to fail to resolve;
     the fallback must be exactly as conservative as today's shipped behavior, never more permissive.
