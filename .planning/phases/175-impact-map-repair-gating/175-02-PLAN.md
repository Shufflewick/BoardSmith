<objective>
Extend the two host modules this phase writes into — the run ledger (decision 17's impact map) and
the `## Verified Against` block (decision 11's re-verification stamp) — without adding a second
write path or a second concept.

Purpose: decision 17 requires the impact map to live in the run-scoped ledger, reusing 173/174's
atomic append + resume mechanism (`173-REVIEW.md` CR-01's defect class is exactly a second write
path). Decision 11 requires a `## Verified Against` stamp recording "re-verified, NO code change" —
research measured that NO existing label expresses this and that `SCOPE_REASONS` encodes a different
concept entirely (why scope was limited, not whether code moved).

Output: two new ledger record kinds parsed and resolved by the existing helpers, and one new
`VERIFIED_AGAINST_LABELS` member with the `chunk-check` flag that writes it.

This plan is file-disjoint from plan 175-01 and runs in the same wave.
</objective>
