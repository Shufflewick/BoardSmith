<objective>
Build VERIFY-04's mechanical halves: detect every un-adjudicated `contradictory` verdict in a run,
format both readings side by side, and record the human's answer — either as a real `### Ruling N`
entry in `RULINGS.md` or, if deferred, as an honest `UNADJUDICATED` record.

Purpose: VERIFY-04. CONTEXT decisions 6 (classification of ALL pairs completes first, then ONE hard
gate before any staleness write), 7 (reuse the existing `### Ruling N` shape exactly, append-only,
embedding both verbatim readings), 8 (deferred/aborted → UNADJUDICATED, still marks chunks stale,
never silently clean), 9 (no bypass flag — "always" means no representable option skips it), and 14
(ONE decision per contradictory FINDING, never per affected chunk — a single finding can touch 6+
chunks).

`trace-check.ts` reads it. This is the FIRST machine write into a human-authored corpus, so it must
follow the existing informal convention exactly and must NOT invent structured supersession syntax
(only ~3 of 62 real rulings across both games use a supersede verb, one direction-reversed).

The real proof material for this gate is already committed at
`175-FIXTURES/174-07-contradictory/` — a real `contradictory` verdict with real `quotedPass1`/
`quotedPass2` and the full `lineFindings[]`. No PDF mutation is needed.

Output: the gate's detection/formatting command, the RULINGS.md append, and the adjudication record.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tool → `RULINGS.md` (human-authored corpus) | First-ever machine write into a file 100% human/skill-authored today; a bad append corrupts the composite source of truth every future `investigate`/`redteam`/`audit` reads |
| human decision → recorded resolution | The one genuine judgment in this phase; the tool must never stand in for it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-175-09 | Tampering | `appendRuling` | mitigate | Append-only, asserted by a `startsWith`-the-original test; `atomicWriteFile` only; throws if `RULINGS.md` is absent rather than creating one |
| T-175-10 | Elevation of Privilege | `verifyImpactAdjudicateCommand` | mitigate | `outcome: 'resolved'` requires non-empty `decision`/`citation`/`rationale`; no `force`/`yes`/env bypass exists anywhere in the module (grep-asserted) |
| T-175-11 | Repudiation | Deferred adjudication | mitigate | `UNADJUDICATED` is a recorded ledger record that keeps the pair PENDING, never silence (decision 8) |
| T-175-12 | Tampering | Ruling-number assignment | mitigate | `parseRulings` is the single authority; a second `### Ruling (\d+)` regex is grep-forbidden (Pitfall 2) |
| T-175-13 | Repudiation | Crash between RULINGS.md write and ledger append | accept | Ordering makes the failure mode safe: the ruling is durable and the pair stays pending, so a re-run re-asks rather than losing the human's answer. A duplicate-ruling guard on re-run is the compensating control. |
</threat_model>
