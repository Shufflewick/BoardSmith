- `DERIVE_CHECK_VERDICTS` is a frozen, eight-member array holding exactly `DerivedLineClassification`'s members in declared order, imported by type (not re-spelled) from `verify-enumerate.ts`, with a compile-time exhaustiveness guard (`Exclude<DerivedLineClassification, (typeof DERIVE_CHECK_VERDICTS)[number]> extends never`) proven, live, to fail `tsc` when a member is removed from the array (demonstrated during execution, then restored).

- `replaceDeriveCheckVerdicts`/`recordDeriveCheckVerdicts`/`readDeriveCheckVerdicts` are the project-level (`rulebook/.derive-check/verdicts.md`, no run-id segment, no `runId` parameter on any of the three) ledger, reusing `atomicWriteFile` — the repo's one atomic write path — for every durable write. `recordDeriveCheckVerdicts` upserts a whole array by `slicePath:lineNumber` key, preserving existing order and appending new/updated keys last; recording slice A then slice B leaves both readable (CR-06).

In summary: import the verdict type rather than re-spell it (interface contract instruction, now compiler-enforced); drop the retired blind-re-derivation-specific fields as a documented finding rather than adapt them; make the record/ledger API array-shaped per the plan's own shape-change note; add a new `recordedAt` field defaulting to now but overridable so re-reads don't drift timestamps forward; use a distinct ledger directory name (`.derive-check` vs. the retired `.derive-recheck`) so the later deletion plan is a clean removal.

## Findings (recorded per plan instruction, not silently resolved)

**The retired ledger's `rederivedValue`/`originalReading`/`rederivedReading`/`factAlignment` fields, and the WR-04 pass-through rule that cross-checked `rederivedValue` against `verdict`, have no analogue under dual enumeration.** Those fields existed because the retired design ran a BLIND second derivation of the same line and needed to record and compare two independent readings of it. Dual enumeration's design is structurally different — two enumerators independently extract facts from the source, a reconciler cross-references a `Derived` line's claim against what both extracted, and `classifyDerivedLines` (`verify-enumerate.ts`) validates the reconciler's citation against grounding-validated evidence before it ever reaches this ledger. There is no "rederived reading" to record or align — the equivalent evidentiary artifact is `groundedQuotes`, verbatim passages both enumerators independently found. This was anticipated by the plan's own instruction ("record it in a header comment and in the SUMMARY... DELIBERATE, DOCUMENTED SEMANTIC CHANGE") and is not a deviation.

## Issues Encountered

One initial test-authoring bug, fixed inline before commit: a "REPLACES the body atomically" test called the sample-record factory function twice to build both the written and expected values, and the factory's default `recordedAt` (`new Date().toISOString()`) legitimately differs by a few milliseconds between the two calls, producing a false-negative diff. Fixed by capturing one record instance and reusing it for both the write and the assertion — not a defect in the module under test, a test-construction mistake caught immediately by the first local test run.
