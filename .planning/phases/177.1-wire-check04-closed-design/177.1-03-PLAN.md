<interfaces>
`analyze.mjs` (177-22-MEASUREMENT) is the REFERENCE IMPLEMENTATION of this pipeline — it runs the
real, unmodified `verify-enumerate.ts` functions in exactly the order the CLI must. Read it before
writing anything. Its steps, in order:

1. `loadFacts` -> `createEnumeratedFact({statement, sourceSentence, numericValue, slicePath})` per
   enumerator fact, for list A and list B.
2. `claimedBoth` <- `reconcile.both.map(b => ({statement, quotedFromA, quotedFromB}))`.
3. `grounding = validateGrounding(listA, listB, claimedBoth)` — returns `{grounded, rejected}`.
4. `groundedByStatement = new Map(grounding.grounded.map(g => [g.statement, g]))`.
5. For each `corroborated-by-composition` proposal: resolve operands, call
   `composeArithmeticClaim({derivedLineText, operation, operands, claimedResult})` or
   `composeArithmeticChain({derivedLineText, steps, operands, claimedResult})`.
6. `claims` <- proposals mapped to `ReconcilerDerivedLineClaim` with `citedFactIds` resolved from
   `citedBothStatements` through `groundedByStatement`, plus `composedFactId` and `absenceTargets`.
7. `provenance = await QuoteVerifiedProvenance.obtain(projectDir)` (per PROJECT, not per slice).
8. `classifyDerivedLines({claims, groundedBoth: grounding.grounded, composed, provenance,
   passages: {[slicePath]: rawSliceText}})`.

`analyze.mjs`'s ONE non-portable element is `ARITHMETIC_LINES` (lines 113-136) — a HAND-IDENTIFIED
operation/operand/claimedResult spec per arithmetic-bearing line. The product has no hand list.
That gap is closed by Task 1 below.

Reconciler RETURN shape today (`reconcile-facts.md:180-205`):

```
{ both: [{statement, quotedFromA, quotedFromB}],
  aOnly: [{statement, sourceSentence}],
  bOnly: [{statement, sourceSentence}],
  derivedLineProposals: [{lineNumber, derivedLineText, proposedClassification,
                          citedBothStatements, arithmeticNote?, absenceTargets?}] }
```
