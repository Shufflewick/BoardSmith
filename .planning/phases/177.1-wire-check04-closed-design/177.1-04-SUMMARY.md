## Accomplishments

- Moved the design-agnostic read machinery — `readLiveSlices` (live `rulebook/*.md` tree, WR-02/WR-10 EACCES-vs-ENOENT distinction), `annotationBody`/`LINE_DECORATION_RE` (CR-01 decoration strip), `quoteLinesOnly` (the shared quote filter every enumerator payload is built from), and `enumerateDerivedLines`/`DerivedLineEntry` — out of the retired `verify-derive-recheck.ts` into `verify-derive-check.ts`. `verify-enumerate.ts`'s `quoteLinesOnly` import is retargeted onto the new module, producing an intentional two-file import cycle with `verify-derive-check.ts` (both usages are inside function bodies, never at module-init time — the full suite staying green is the proof, not a comment claim).
- Added a new guard, `DERIVED_CITATION_LEGEND_PLACEHOLDER_RE`, carrying the measurement harness's disclosed 177-21 fix (a `Derived (p.N):` occurrence with no digit in its citation body — the literal annotation-convention legend text some rulebooks like `doom-machine/rulebook/CARDS.md` write to explain the convention itself) into the product's candidate enumeration for the first time; the retired module never needed this fix because its own real pipeline happened never to be exercised against an undecorated legend line.
- Built `verifyDeriveCheckCommand`: enumerates every live-tree `Derived` line PROJECT-WIDE (proven behaviorally deeply-equal against a `.verify/<run-id>/slices/` + `rulebook/source/` decoy tree, never reading either), joins each candidate to the project-level ledger (CR-03 stale-text join, WR-03 orphan reporting), names the three pinned model ids (`DERIVE_CHECK_MODELS` — `claude-opus-5`/`claude-haiku-4-5-20251001`/`claude-sonnet-5`) as string literals, and hands back the exact `buildEnumeratorPayload` bytes plus `derivedLines` for every slice with at least one pending candidate. Never assigns `process.exitCode` anywhere (pinned by both a behavioral test against a `contradicted` record and a source-level grep-count test) — advisory, exit 0 unconditionally, per CONTEXT decision 14.
- Registered both `verify-derive-check` and a retargeted `verify-derive-record` in `cli.ts`, replacing the retired `verify-derive-recheck` registration. Rewrote the CHECK-04 comment block to describe the dual-enumeration design and name the eight-verdict set, while preserving the two load-bearing sentences verbatim in spirit (project-level/source-free by construction, no `--run-id`/bypass option; `verify-derive-record` is the ONLY write surface). `verify-derive-record`'s flag set is exactly `--project`/`--slice-path`/`--enumerator-a`/`--enumerator-b`/`--reconciler`/`--json` — no `--verdict`, no bypass flag.
- New `src/cli/cli.test.ts` (4 tests): spawns the real `bin/boardsmith.js` entry point as a child process — `verify-derive-check --help` exits 0 and names its flags; a real end-to-end run against a temp project exits 0 and emits parseable, non-empty `slices`/`models` JSON; `verify-derive-recheck` (no `--help`) exits non-zero with commander's own "unknown command" error; `verify-derive-record --help` lists exactly its six new flags and none of the nine retired ones.
- 17 new tests in `verify-derive-check.test.ts` for `verifyDeriveCheckCommand` covering every `<behavior>` bullet in the plan (no-ledger/all-pending, project-wide decoy-tree equality, legend exclusion x2, payload emission/suppression, `payloadError` on a forced `buildEnumeratorPayload` throw, CR-03 stale join, WR-03 orphan, missing-`rulebook/`, EACCES, `--json` stdout-only, `process.exitCode` unset on `contradicted`, and both grep-count source pins).

## Next Phase Readiness

`boardsmith verify-derive-check` and `boardsmith verify-derive-record` are both real, invocable CLI commands today. Downstream plans need to know:

- **The literal command a designer now runs**: `boardsmith verify-derive-check --project <dir> [--json]` — read/report, always exits 0. To dispatch and record: `boardsmith verify-derive-record --project <dir> --slice-path <path> --enumerator-a <file> --enumerator-b <file> --reconciler <file> [--json]`.
- **The exact `--json` shape 177.1-05's Step 7 rewrite must format**: `{ projectDir, models: { enumeratorA, enumeratorB, reconciler }, slices: [{ slicePath, candidates, enumeratorPayload?, payloadError?, derivedLines: [{ lineNumber, text }] }], findings: [{ slicePath, lineNumber, derivedLineText, verdict, reason, citedFactIds, status: 'recorded'|'pending' }], verdictCounts (all 8 keys), pendingCount, staleRecords: string[], orphanedRecords: string[], groundingRejections: [] (always empty from this command), missedFactCount: 0 (always 0 from this command) }`. `enumeratorPayload` is present only on slices with a pending candidate; dispatch it to two independently-modeled enumerators (`models.enumeratorA`/`models.enumeratorB`), have a `models.reconciler` dispatch reconcile-facts.md against both returns plus `derivedLines`, then call `verify-derive-record` with the three returns as files.
