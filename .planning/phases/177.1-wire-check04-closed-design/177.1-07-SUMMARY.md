## Deviations from Plan

**1. [Rule 3 — blocking-issue fix, scope widened per the plan's own sweep instruction] Edited
files outside the plan's declared `files_modified` list.** The plan's frontmatter named 8 files;
the required repo-wide orphan-reference sweep (Task 1's own action text) touched 4 more:
`verify-enumerate.ts`, `derived-line-pattern.test.ts`, `verify-derive-check.ts`,
`verify-derive-check.test.ts`. Every edit was a comment/prose update, never a behavioral change.
Not a deviation from intent — the plan's acceptance criteria (`grep -rn ... src/ docs/ returns
zero hits`) is repo-wide by construction and cannot be satisfied without touching every file that
mentions the retired module by name.

**2. [Rule 2 — auto-add missing critical functionality] Ported 10 direct unit tests for
`annotationBody`/`quoteLinesOnly`/`enumerateDerivedLines` that the port-coverage audit found
missing.** These three functions were moved verbatim (or near-verbatim) into
`verify-derive-check.ts` in an earlier wave (177.1-02), but their own dedicated test coverage
was never ported alongside them — only indirect exercise through higher-level command tests
existed. The plan's Task 1 rule ("Any UNPORTED row STOPS this task — port it or escalate")
applies here even though the underlying *source* had already been moved; what was missing was
the *test*, which the deletion of `verify-derive-recheck.test.ts` would otherwise have silently
dropped. Closed by porting rather than escalating, since the fix was cheap and the original
assertions transferred with zero adaptation.

**3. [Grep-criterion interpretation, documented rather than silently applied] Task 1's literal
acceptance-criteria grep (`verify-derive-recheck|BS-DERIVE-V1|BS-DERIVE-COMPARE-V1|
buildBlindDerivePayload|blindDeriveHandle|focusQuoteWindow|FACT_ALIGNMENTS|DERIVE_VERDICTS|
\.derive-recheck`) returns 3 remaining hits, all inside pre-existing (177.1-05) or newly-added
absence-type test assertions, never live code:**
- `src/cli/cli.test.ts:13,80,82,85` — a pre-existing test proving `verify-derive-recheck` is an
  unreachable CLI command name (spawns the real CLI, asserts a non-zero/error result). Editing
  this to remove the literal string would require testing a DIFFERENT, less specific claim
  (any bogus command name is rejected) — weakening the proof, not satisfying the criterion's
  intent (no live reference to the retired design).
- `src/cli/slash-command/bs/verify.test.ts:732` (formerly ~940) — a pre-existing (177.1-05)
  `ABSENCE gate` test asserting `verify-game.md` contains none of `BS-DERIVE-V1`,
  `BS-DERIVE-COMPARE-V1`, `buildBlindDerivePayload`, `factAlignment`, `verify-derive-recheck` —
  the array of retired identifiers IS the test's payload; removing the literal strings would
  make the gate assert nothing.
- Task 2's own required absence probe (this plan, `verify.test.ts`, the new `installer leaf
  probes` test) necessarily embeds the literal filenames `derive-recheck.md`/`derive-compare.md`
  as the strings whose non-existence it proves.

All three are structurally identical to the pattern Task 2's own acceptance criteria explicitly
carves out ("except inside the absence probe"). None imports, dispatches, or depends on the
retired module; each is itself a proof that the retired thing is gone. Recorded exact locations
and counts per the plan's own instruction ("state the exact count and its location in the
SUMMARY").

**4. [Process] Task 1 and Task 2 were committed together as a single atomic commit
(`ec6fc57d`), rather than two separate task commits, plus a small follow-up commit
(`873106f2`) for the port-coverage gap closure discovered while auditing Task 1.** The plan's
own critical_rules were explicit: "Delete files and their pins in the SAME commit... Atomic per
unit." Since the code deletion (Task 1) and the pin removal in `verify.test.ts` (Task 2) are
exactly that kind of unit — an intermediate commit with the files gone but
`verify.test.ts`'s `derive-recheck.md`/`derive-compare.md` describe blocks still present would
be red — they were committed together to guarantee no intermediate red state ever existed in
git history.
