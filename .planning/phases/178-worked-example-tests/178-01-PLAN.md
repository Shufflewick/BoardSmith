<measured_hazard>
Already measured at plan time — this is the load-bearing constraint for this plan, not a guess:

  node -e "const re=/^[^A-Za-z0-9]*(?:Derived|Visual|Named-but-undefined|Example)\b/im;
           console.log(re.test('\"example: 5, 5, 5\"'))"   // => true

`seven/rulebook/01-definitions-and-components.md:6` contains the REAL quote line
`"example: 5, 5, 5"`. `ANNOTATION_VOCABULARY_RE` is case-insensitive and tolerates leading
non-alphanumeric decoration (the opening `"`). Naively appending `'Example'` to
`ANNOTATION_FAMILIES` therefore makes `buildEnumeratorPayload`'s construction-site backstop THROW
on `seven`'s slice — breaking a CLOSED requirement's live pipeline.

Also measured: `grep -rn "Example (p\." ~/BoardSmithGames/{seven,one-two-punch,doom-machine}/rulebook`
returns ZERO lines today. No reference game carries the marker, so a citation-keyed
`Example (p.N):` recognizer is behavior-neutral on the entire existing corpus.
</measured_hazard>
</context>
