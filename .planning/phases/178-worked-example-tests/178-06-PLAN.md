## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model-generated test code → generated project's test directory | LLM output becomes code that a test runner will execute |
| `--chunk` slug → filesystem path | Caller-supplied slug composes a write path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-178-12 | Tampering | generated test code | mitigate | `scanGeneratedTestCode` runs the measured subset of the seven sandbox rules BEFORE write; execution happens only via the project's own `vitest run`, never `eval`/`new Function` |
| T-178-13 | Elevation of privilege | `--chunk` path composition | mitigate | `generatedTestFilePath` rejects separators and `..`; writes confined to `tests/examples/` |
| T-178-14 | Tampering | cross-artifact writes | mitigate | Emitter never writes the ledger and record never writes a test file; both asserted by test |
| T-178-SC | Tampering | npm/pip/cargo installs | mitigate | No installs; any addition requires a blocking human checkpoint |
</threat_model>
