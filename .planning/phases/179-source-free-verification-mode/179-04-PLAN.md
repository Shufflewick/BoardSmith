<interfaces>
Available to the skill as of plan 03:
- `boardsmith verify-close-record --project <dir> [--run <run-id>] [--json]` → writes the
  `## Verified Against` block for every chunk the pass evaluated, and reports
  `{ scope, reason?, runId?, recorded: [{ slug, changed }], errors: [{ slug, message }] }`. Exit 0
  always, absent a tool failure — deliberately unlike `chunk-check`, because a Close reports rather
  than gates. Idempotent: a re-run with no state change writes no file. `--run` is supplied only on
  the full path, where a staging run ledger exists; source-free mode omits it.

Available to the skill as of plan 02:
- `boardsmith verify-source-free-check --project <dir> --json` → `{ sourceFree, scope, reason,
  stepsRun[], stepsSkipped[], uncheckedDefectClasses[] (each `{ stepId, defectClass,
  wouldHaveBeenCaughtBy }`), checksRun[] }`. Exit 0.

The four source-free commands the reduced sequence dispatches:
`boardsmith trace-check --json` (CHECK-03), `boardsmith drift-check --json` (CHECK-05),
`boardsmith verify-derive-check --json` + `verify-derive-record` (CHECK-04, Step 7),
`boardsmith verify-example-replay --json` + `verify-example-translate` + `verify-example-record`
(CHECK-06, Step 8).

Skill-file house rules, already held everywhere in `verify-game.md`: steps DISPATCH and FORMAT,
never compute; every number in a report comes from a command's `--json`; advisory checks exit 0;
reference files are cited by `${CLAUDE_SKILL_DIR}/../bs-shared/verify/<file>.md`.
</interfaces>
